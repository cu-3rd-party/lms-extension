# Формат профиля настроек

Файл, в который расширение выгружает настройки и из которого их загружает.
Формат публичный: им делятся, его будут отдавать и принимать через сервис, а
значит в него приедет что угодно — от версии постарше до намеренно кривых
значений. Всё, что описано ниже, проверяется на загрузке;
[`settings_registry.js`](src/plugins/_shared/settings_registry.js) —
единственное место, где это знание живёт.

## Конверт

```json
{
  "format": "cu-lms-extension/profile",
  "version": 1,
  "kind": "settings",
  "meta": {
    "name": "Тёмный минимал",
    "author": "",
    "note": "",
    "createdAt": "2026-09-21T18:40:00.000Z",
    "extensionVersion": "2.6.0"
  },
  "values": {
    "themeEnabled": true,
    "backgroundFit": "cover"
  }
}
```

| Поле      | Обязательно | Смысл                                                               |
| --------- | ----------- | ------------------------------------------------------------------- |
| `format`  | да          | Метка формата. Не совпала — файл не наш, дальше не смотрим          |
| `version` | да          | Версия **формата**, не расширения. Больше текущей — отказ           |
| `kind`    | нет         | Какой набор выгружали: `settings`, `visual`, `full`                 |
| `meta`    | нет         | Название, автор, заметка, дата, версия расширения — только для глаз |
| `values`  | да          | Сами настройки: `ключ → значение`                                   |

`version` растёт, когда меняется структура **конверта**. Добавление новых
ключей в `values` версию не меняет: незнакомый ключ загрузчик пропускает и
сообщает об этом, поэтому старое расширение спокойно читает новый файл.

## Наборы (`kind`)

| Набор      | Что входит                                               | Размер           |
| ---------- | -------------------------------------------------------- | ---------------- |
| `theme`    | только своя палитра и свой CSS                           | килобайты        |
| `settings` | оформление, тема, функции, интеграции — только поведение | килобайты        |
| `visual`   | оформление, тема + свои картинки: обложки, логотип, фон  | до нескольких МБ |
| `full`     | всё вышеперечисленное плюс названия курсов и свой архив  | до нескольких МБ |

`theme` стоит особняком: тема — это текст, она весит килобайты и ей делятся
отдельно от всего остального. Выгружает и загружает его попап — раздел «Выбор
темы», кнопки «Сохранить тему в файл» и «Загрузить тему из файла». В редакторе
тем файлов нет: он правит текущую тему, файлами заведует меню.

Картинки лежат внутри JSON как `data:`-URL. Это делает файл самодостаточным —
важное свойство для обмена, — но `visual` из-за этого весит мегабайты. Сервису
стоит хранить их отдельными файлами, а не строками в JSON.

## Что не попадает в файл никогда

Группа `private` в реестре. Сейчас это:

- `akh_token`, `akh_refresh_token` — токены доступа к АКХ. Отдать их вместе с
  настройками означало бы отдать доступ к аккаунту;
- `swapDeviceKey` — ключ устройства для биржи обмена парами;
- `courseMetaCache`, `cachedLatestVersion`, `lastVersionCheckTimestamp` — кеши,
  в чужом профиле бесполезны;
- `futureExamsScheduleCache`, `futureExamsConfigCache` и их `…Timestamp` —
  расписание контрольных с сервера и время его загрузки: кеш, приедет заново;
- `lmsOrigin` — домен последней навигации, вычисляется сам;
- `themePickerActive`, `themePageValues`, `themePickResult`, `themeEditorTabId`,
  `themeSourceRequest`, `themeSourceDump` — через них вкладка редактора тем и
  страница LMS договариваются о пипетке и о выгрузке стилей. Состояние одного
  сеанса, к теме отношения не имеет.

Правило на будущее: **любой новый ключ появляется в реестре**, и если это токен,
кеш или что-то, привязанное к конкретному устройству, — он идёт в `private`.
Ключ, которого нет в реестре, при загрузке отвергается, так что забытый ключ
просто не перенесётся; а вот забытый секрет в группе `content` утечёт.

## Что происходит при загрузке

1. Разбор JSON, проверка `format` и `version`.
2. Каждый ключ из `values` ищется в реестре:
   - нет в реестре → пропуск, «расширение не знает такой настройки»;
   - группа `private` → пропуск, «такие ключи не переносятся»;
   - не тот тип, значение вне диапазона или не из списка → пропуск с причиной.
3. Попап показывает, сколько применится и сколько пропустится, и **спрашивает
   подтверждение** — загрузка перезаписывает то, что человек настраивал руками.
4. Записывается только то, что прошло проверку; остальное хранилище не трогается.

Разбор (`inspect`) и запись (`apply`) разделены намеренно: сервису тоже
понадобится показать содержимое пака до установки.

## Чего формат пока не умеет

- **Частичного применения по выбору.** Загружается весь файл целиком; выбрать
  «только цвета, без картинок» нельзя.
- **Подписи и происхождения.** В файле нет ничего, что подтверждало бы автора.
  Для сервиса это придётся добавлять на его стороне — в самом файле поле
  `meta.author` заполняет кто угодно.
- **Ключей из `localStorage` страницы.** Метод скипа, свои фильтры заданий и
  архив ведомостей лежат не в хранилище расширения, а в `localStorage` самой
  LMS, поэтому в профиль не попадают.
