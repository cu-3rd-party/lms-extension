# Офлайн-копия LMS

LMS иногда не работает целиком (отключают дата-центры). Пока она работает,
расширение понемногу сохраняет то, что выбрал студент. Когда LMS не открывается,
попап → «Офлайн» → **«Открыть LMS офлайн»** показывает минимальную копию LMS из
сохранённых данных. Кнопка **«Сохранить копию на диск»** скачивает её одним zip:
после распаковки копия открывается двойным кликом, без плагина.

Работает одинаково в Chrome/Chromium, Firefox и Safari. Поэтому на диск
сохраняется только zip, без «живой» папки: выбрать папку и писать в неё умеет
только Chromium (`showDirectoryPicker`), а API загрузок нет в Safari.

## Файлы

| Файл                | Где работает                | Что делает                                                                |
| ------------------- | --------------------------- | ------------------------------------------------------------------------- |
| `offline-sync.ts`   | фон (импорт в background)   | Что и когда скачивать, очередь, лимиты, откладывание при неудачах, статус |
| `offline-fetch.ts`  | вкладка LMS (executeScript) | Один запрос к API с куками вкладки; функция переезжает во вкладку текстом |
| `offline_store.js`  | фон и страница              | IndexedDB `culms-offline`: таблицы `records`, `files`, `meta`             |
| `offline.html`      | страница расширения         | Страница «LMS офлайн»                                                     |
| `offline_viewer.js` | страница и архив            | Минимальная LMS: курсы, лонгриды, задания, расписание                     |
| `offline_export.js` | страница расширения         | «Сохранить копию на диск»: zip (fflate из `_shared`)                      |
| `offline.css`       | страница и архив            | Стили в оформлении LMS; тёмная тема — по системной                        |
| `fonts/`            | страница и архив            | Inter — шрифт LMS (кириллица и латиница, 67 КБ) и его лицензия OFL        |

Все файлы страницы перечислены в `web_accessible_resources` в
`manifest.config.js`: без этого их нет в `dist`.

## Что и как часто

| Раздел (настройка)                       | Запросы                                                                             | Обновление                                                                         |
| ---------------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Лонгриды (`offlineCacheLongreads`)       | `courses/{id}/overview`, `longreads/{id}/materials`, файлы и картинки               | Один раз, **не обновляются**; новые лонгриды берутся из обзора курса (раз в сутки) |
| Условия ДЗ (`offlineCacheHomework`)      | те же материалы: задания `coding`/`questions` и их вложения                         | Один раз, не обновляются                                                           |
| Мои решения (`offlineCacheSolutions`)    | `tasks/{id}` (решение, оценка, условие) и файлы решения — только за последний месяц | Когда в списке заданий меняются статус, оценка или даты                            |
| Задания и дедлайны (`offlineCacheTasks`) | `tasks/student` со всеми статусами; хранятся только за последний месяц и будущие    | Раз в 2 часа                                                                       |
| Расписание (`offlineCacheTimetable`)     | `students/me/timetables`                                                            | Раз в сутки                                                                        |

Профиль не качается: вкладку «Профиль» убрали (12.10.2026), а `student-hub`, откуда
он брался, в тот день и не отвечал.

Общий тумблер — `offlineCacheEnabled`, по умолчанию выключен. Категории по
умолчанию включены. `offlineMaxFileMb` (250 МБ) — файлы больше не качаются.
Видео и аудио из лонгридов не качаются никогда, `tasks/{id}/events` не
запрашивается (там чужие данные). Файл хранится под ключом
`filename@version`: LMS меняет `version` при замене файла, поэтому одно и то же
содержимое не качается дважды.

Курсы — только текущие (`courses/student?state=published`), архив не трогаем.
**Сначала выбор курсов, потом скачивание.** Выбранные курсы лежат в
`offlineCourseIds` (storage.sync, id курсов). Пока ключа нет, после включения
качается только список курсов (попап сам просит его, если списка ещё нет), а
в блоке «Курсы» — галочки без отметок и кнопки «Отметить все», «Снять все»,
«Начать скачивание (N)». До неё галочки — черновик. «Скачать всё»
недоступна, пока не отмечен ни один курс; с отмеченными она сама сохраняет
выбор и сразу качает всё — «Начать скачивание» жать не обязательно. После
выбора каждая галочка сохраняется сразу; новый курс (новый
семестр) не качается, пока его не отметят. Изменение `offlineCourseIds` фон
ловит в `storage.onChanged` и сразу начинает заход.

Невыбранные курсы не качаются вовсе — ни структура, ни лонгриды, ни решения.
А то, что успело скачаться раньше (курс сняли позже), не
показывается: `onlyChosenCourses()` в просмотрщике выбрасывает из записей
структуру, лонгриды, задания и решения и строки расписания по невыбранным
курсам. Через неё же данные идут в архив, так что и в `data.js` их нет.

**Ведомости, посещаемость и профиль не качаются** (решили 12.10.2026). Записи,
которые успели скачать прежние версии, `onlyChosenCourses()` тоже отбрасывает:
она пропускает только известные виды записей.

**Старые задания не нужны.** Задание старше 30 дней (по дедлайну, без него —
по отправке или созданию) не хранится в списке и не перечитывается ради
решения: из ~760 заданий за всё время остаются десятки. Дедлайн в будущем —
всегда нужен.

## Как не нагрузить интернет

- Заходы: по `alarms` раз в 5 минут и при открытии страницы LMS (не чаще раза в
  3 минуты). Заходы не пересекаются.
- За заход — не больше 20 запросов и 40 МБ, между запросами 0,8 с.
- Кнопка **«Скачать всё»** снимает лимит: заход идёт до конца очереди, пауза
  0,2 с (LMS всё равно обрабатывает запросы студента по одному, ~120 мс).
  Нажатая посреди обычного захода — снимает лимит у него. Пока идёт, кнопка
  становится «Остановить»: текущий запрос доделывается, дальше — снова по
  таймеру. Останавливает её и «LMS не отвечает» — как обычный заход.
- Очередь (`survey()`) — что нужнее офлайн:
  1. список курсов и обзоры выбранных курсов;
  2. **лонгриды от новых к старым** (по `publishedAt`), каждый сразу со своими
     файлами — свежая неделя скачивается целиком раньше старых;
  3. задания и расписание;
  4. решения за месяц и их файлы.
- Очередь пересчитывается перед каждым запросом: из обзора появляются
  лонгриды, из лонгрида — его файлы, и они встают сразу за ним.
- Каждое задание оставляет след (данные, отметка об ошибке или о неудачном
  файле), поэтому повторно в очередь не попадает; если первым снова оказалось
  то же самое, заход останавливается. Ошибки по отдельной записи (403, 404,
  файл не скачался) повторяются через сутки.

## Как попасть в копию, когда LMS лежит

Кнопка плагина живёт на странице LMS — если LMS не открывается, меню не
открыть, а про кнопку на панели браузера студент может не знать. Поэтому
(`offline-entry.ts`):

- **`my.centraluniversity.ru/offline`** (и `my.cu.ru/offline`) —
  `webNavigation.onBeforeNavigate` перехватывает переход до запроса к LMS
  и открывает копию. Работает и при живой LMS.

Сами в копию не перекидываем, даже если LMS не открылась: плагин может
ошибиться, а студент тогда не попадёт в работающую LMS (решили 12.10.2026).

## Справка в попапе

Во вкладке «Офлайн» первым блоком — «Как это работает» (`#offline-help`,
свёрнут): что это, как начать, когда качается, как сохранить копию на диск
(zip) и что пересылать, где хранится копия. Текст — в `popup.html`; при
смене поведения выгрузки его надо поправить вместе с этим README.

## Терминал в попапе

Во вкладке «Офлайн» под кнопками — тёмный блок, как терминал:

- **размер копии** — первой строкой; в строке статуса над терминалом —
  разбивка: файлы (и сколько их) и «тексты и списки» (записи как JSON в
  UTF-8, `dataBytes` в `OFFLINE_STATUS`, пересчитывается, только когда
  записи поменялись). Тот же размер — в шапке страницы «LMS офлайн» рядом с
  датой копии;
- **прогресс по разделам**: структура курсов, лонгриды, файлы лонгридов и
  условий (с объёмом и числом пропущенных больших), задания и списки, решения
  за месяц, файлы решений — «скачано / всего» и полоска;
  ниже — что качается следующим и сколько ещё в очереди;
- **лог**: каждый запрос строкой со временем — ✓ скачано (у лонгрида — число
  блоков, у файла — размер), – пропущено (ответ 403/404/5xx другого сервиса,
  файл больше лимита), ✗ ошибка, синие ▶/■ — начало и итог захода.

Лог — последние 300 строк в `meta.log`; попап показывает последние 120 и
обновляется раз в 2 секунды, пока открыта вкладка. Прогресс считает тот же
`survey()`, что строит очередь, так что «всего» всегда совпадает с тем, что
будет скачано.

## Откуда запросы

Запрос к API идёт **из вкладки LMS** (`scripting.executeScript` с
`fetchLmsJsonInTab`): на её домен и с её куками, одинаково во всех браузерах.
Если вкладки LMS нет — из фона с `credentials: 'include'`; Safari куки LMS
из фона может и не отдать, тогда докачка ждёт, пока студент откроет LMS.

Файлы фон качает сам: `content/download-link` отдаёт подписанную ссылку на
хранилище, куки для неё не нужны. С октября 2026 это Selectel
(`university-lms-materials.s3.ru-7.storage.selcloud.ru`, раньше
`storage.yandexcloud.net`): его CORS отвечает любому Origin, включая
`chrome-extension://` и `moz-extension://`, так что разрешение в манифесте под
него не нужно (проверено 12.10.2026).

Ответы:

- 401 или не JSON (страница входа) — заход прекращается, в попапе «войди в LMS»;
- сеть или 5xx от `micro-lms` — заход прекращается, следующий автоматический откладывается:
  5 мин, 10, 20… до 2 часов. Кнопка «Скачать всё» откладывание не ждёт.
  В попапе — «LMS не отвечает… открой LMS офлайн»;
- 403/404 и 5xx от других сервисов — запись помечается ошибкой, остальное
  качается дальше. LMS падает по частям: 12.10.2026 `micro-lms` работал, а
  `student-hub` (профиль) отдавал 502 — из-за таких выгрузка вставать не должна.

Состояние — в `meta.state`: `lastRunAt`, `lastSuccessAt`, `lastError`,
`reason` (`auth` / `down`), `failures`, `nextRunAfter`.

## Сообщения фону

| action             | Ответ                                                                                                                                  |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `OFFLINE_STATUS`   | `{ enabled, state, running, full, coursesChosen, progress, pending, next, files, bytes, dataBytes, courses, log, hasData }` для попапа |
| `OFFLINE_SYNC_NOW` | «Скачать всё»: заход без лимита до конца очереди; ответ сразу, не ждёт конца                                                           |
| `OFFLINE_STOP`     | «Остановить»: заход кончается после текущего запроса                                                                                   |
| `OFFLINE_CLEAR`    | Удаляет всю копию (IndexedDB)                                                                                                          |
| `OPEN_OFFLINE`     | Открывает `offline/offline.html` вкладкой (одна на всех, как у редактора тем)                                                          |

## Страница и архив

`offline_viewer.js` один на два режима. На странице расширения данные берутся из
IndexedDB, а файлы отдаются как `blob:`. В распакованном архиве данные лежат в
`_offline/data.js` (`window.CU_LMS_OFFLINE_DATA`), а файлы — по относительным
путям. Данные в `.js`, а не в `.json`: страница, открытая с диска, соседний
JSON прочитать не может, а `<script src>` — может.

HTML из LMS (текст лонгрида, описание задания) чистится: убираются `script`,
`iframe`, `on*`-атрибуты и `javascript:`-ссылки. На странице расширения их
не пустил бы CSP, а у архива на диске CSP нет.

### Оформление как в LMS

Размеры и цвета замерены на живой LMS (12.10.2026, окно 1440×900,
`getComputedStyle` через встроенный браузер); полный список — в шапке
`offline.css`. Коротко:

- шапка 72px и меню 320px — белые, без рамок; пункты меню 40px, радиус 12,
  названия и порядок как в LMS: Курсы, Ведомости, Мои задания, Мои пары,
  Посещаемость (+ Профиль);
- «Мои курсы» — единственная страница на сером `#f4f4f5`: белый «остров» с
  заголовком (радиус 24) и сетка маленьких белых карточек (радиус 16, зазор 8) со значком и названием категории курса (`category`: withoutCategory →
  «Без категории», stem, mathematics, general, softSkills, development,
  business, ml); обложек в LMS нет;
- курс: хлебные крошки 16/40 через «›», заголовок 700 32/40, темы —
  аккордеоном (строка 56px с круглой бирюзовой иконкой, свёрнуты), лонгриды —
  строками 48px с отступом 64px;
- лонгрид: «К списку всех тем», без подложки, текст 16/24; вложение — плашка
  с тонкой рамкой, зелёной иконкой файла и кнопкой скачивания; задание —
  карточка с рамкой (радиус 20): бейдж статуса (точка и подпись, цвета LMS:
  серый «Не начато/В работе», голубой «На проверке», зелёный «Проверено»,
  красный «Не сдано/На доработке»), название 600 20/28, «Дедлайн: Пт, 18
  сентября в 22:00» (красным, если просрочен) и «9/10 баллов»;
- «Мои пары»: у каждой пары кнопка «Трансляция» — комната Контур.Толка
  `centraluniversity.ktalk.ru/{calendarEventId без дефисов}`, как в плагине
  трансляций (`timetable/timetable_join.js`); аудитория и преподаватели — в
  обоих форматах LMS (строка или `{ title, building }`, `host` или `hosts`);
- «Мои задания»: вкладки-пилюли (активная тёмная), таблица без шапки:
  название и курс, бейдж, баллы «6/10», дедлайн «Ср, 03 дек. 17:00».

Шрифт — Inter, как у LMS; файлы взяты из её сборки (`assets/kit/fonts`) и
лежат в `fonts/`, потому что офлайн его не скачать. Иконки — свои,
нарисованные в духе иконок LMS (её svg не копируем). Логотипа нет:
в шапке — «LMS офлайн», дата и размер копии. Тёмная тема — по системной
(по палитре тёмной темы LMS), на узком экране меню уходит полосой под шапку.

В архив шрифт кладётся в `_offline/fonts/` вместе с OFL.txt. Страницы
лонгридов в архиве несут стили внутри себя (чтобы жить и в пересланной папке
курса) и берут шрифт из `_offline/fonts` по относительному пути — нет папки,
будет системный.

Раскладка архива:

```
LMS офлайн ГГГГ-ММ-ДД.zip
├── Открыть LMS офлайн.html
├── README.txt
├── _offline/                 код страницы и data.js (личное: решения и оценки за них)
└── Курсы/<курс>/<NN. тема>/<NN. лонгрид>/
    ├── <лонгрид>.html        текст лонгрида и заданий, ссылки на файлы рядом
    ├── файлы лонгрида и условий
    └── Моё решение/
```

Папку курса можно переслать как есть. Имена приводятся к допустимым в Windows,
macOS и Linux (`:` → `_`, длина до 60 символов), одинаковые получают « (2)».
Файл, который встречается в нескольких лонгридах, кладётся один раз.
PDF и картинки идут в zip без сжатия: они и так сжаты, а так в разы быстрее.

## Тест

`tests/offline-cache.test.ts` — подставная LMS через `context.route`, fetch
service worker'а подменён для хранилища файлов. Проверяет: «LMS лежит» →
откладывание; выгрузку всего выбранного без огромного файла; лонгриды раньше
заданий и файлы сразу за своим лонгридом; что до выбора курсов качается только
их список, а «Скачать всё» недоступна, пока не отмечен курс; кнопку «Начать скачивание»; что
невыбранный курс и задание старше месяца не запрашиваются и не видны на
странице и в архиве; терминал в попапе; шрифт Inter без сети; что второй заход
ничего не перекачивает; страницу офлайн по всем разделам и чистку HTML; zip, его
раскладку и открытие распакованной копии с диска.

```bash
bun run build:chrome
bun run test offline-cache
```
