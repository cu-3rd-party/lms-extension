# Плагин `attendance` — посещаемость семинаров

**URL:** `/learn/attendance/courses` (список курсов) и `/learn/attendance/courses/{id}` (курс).
Не путать с `/learn/attendance-management` — это раздел преподавателей, туда
плагин не внедряется.

Родной раздел показывает по курсу только «N из M за весь семестр», а внутри
курса — пары **одного дня**, по умолчанию сегодняшнего, причём всех групп
сразу. Чтобы проверить себя, надо помнить даты своих семинаров и перебирать их
в календаре. Плагин собирает семестр целиком.

Считаются только семинары: лекции LMS в посещаемость не отдаёт вовсе.

---

## API LMS

| Запрос                                                                | Что отдаёт                                                                                                     |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `GET /api/micro-lms/v0/attendance/learn/courses?isArchived=false`     | Курсы: `isVisibleForStudents`, `stats { attendedCount, enrolledCount, percent }` — то, что в «За весь семестр» |
| `GET /api/micro-lms/calendar-events/learn/courses/{id}/events/{дата}` | Все семинары курса за день, у своего `isParticipant: true`                                                     |
| `GET /api/micro-lms/v0/attendance/learn/courses/{id}/events/{дата}`   | `eventId` пар дня, на которых студент отмечен. У курса с закрытой посещаемостью — 403                          |
| `GET /api/micro-lms/students/me/timetables`                           | Своё расписание: у семинара день недели, `interval` (1 или 2 недели), `startDate`/`endDate`                    |

Важно:

- `eventId` — это id **серии** занятий (тот же, что `calendarEventId` в
  расписании), а не одного дня. Поэтому отметка ищется по паре «дата + id».
- `calendar-events` отвечает и по курсам с закрытой посещаемостью, и по
  будущим датам; отметки — только по открытым.
- `enrolledCount` («За весь семестр») бывает меньше, чем семинаров в
  календаре: последние (зачётные) недели в него не входят. Поэтому «за
  семестр» берётся из LMS, а «впереди» — по расписанию.
- Фаза «раз в две недели» отсчитывается от `startDate` серии (проверено на
  живом курсе: старт 21.09, пятница — пары 25.09, 09.10, …).

## `attendance_api.js`

Общий загрузчик, `window.cuLmsAttendance`. Оба скрипта ниже зовут `load()`;
загрузка одна на всех и живёт минуту.

**Как собирается семестр.** По расписанию считаются даты своих семинаров
каждого курса. Для прошедших дат — два запроса (пары дня и отметки), для
будущих — ничего: они «впереди». Если в прошедший день своей пары в LMS нет
(праздник, перенос), занятие помечается «пары не было» и в счёт не идёт.

Если курса нет в расписании (сменил группу, курс вне сетки), проходим все
дни от начала семестра до сегодня: сначала пары дня, а отметки — только если
своя пара нашлась. Будущих пар для такого курса не видно.

**Статусы:** `attended` (был), `missed` (не был), `pending` (пара была меньше
недели назад и без отметки — LMS сама пишет «если посещение не отобразилось
спустя неделю — свяжись с поддержкой»), `upcoming` (впереди, в том числе
сегодняшняя, если ещё не кончилась), `none` (пары не было).

**Счёт по курсу** (`countsOf`): процент — от пар с окончательной отметкой
(`attended / (attended + missed)`); «ждут отметки» в процент не входят; макс. —
`за семестр − пропуски`, то есть сколько выйдет, если ходить на все
оставшиеся.

**Кеш.** Ответы по дням лежат в `localStorage['culms.attendance.cache.v1']`
(только свои пары и отметки). Ответ, полученный позже, чем через 8 дней после
пары, считается окончательным и больше не запрашивается; свежие — каждый раз
заново. Записи старше 200 дней выкидываются. Одновременно — не больше 6
запросов к LMS.

## `attendance_summary.js`

Страница «Посещаемость курсов».

- **Дописка в колонку «За весь семестр»** (только «Актуальные»): под числом
  LMS одна строка, как K/D/A в CS, — «был / мог быть / всего», например
  «5/9/26»: был на 5, своих семинаров уже прошло 9 (вместе с теми, что ждут
  отметки), за семестр по LMS — 26. «Был» красится по норме (доля посещённых
  из прошедших с отметкой). Что значат числа — одной подписью под таблицей
  (`#culms-att-native-legend`); в подсказке строки — процент, сколько ждут
  отметки и максимум к концу семестра. Курс ищется по названию строки — у
  строк в разметке нет id. Сравниваются только буквы и цифры («Сердечки»
  меняют 🔴 на ❤️ прямо в тексте), а если курс переименован своими названиями
  (`_shared/course_names.js`), оригинал берётся из `data-culms-orig-name`
  через `cuLmsCourseNames.originalFor`.
- **Вкладка «Сводная»** после «Архивные». Как «Сводная таблица» в ведомостях:
  глубокая копия родной вкладки (ради стилей), клик перехватываем, родные
  таблица и заглушка прячутся классом `culms-att-on`, плашка про поддержку
  остаётся. Пока открыта наша, у родной снимается `active`, а при уходе
  возвращается той, на чей адрес указывает страница. `#summary` в адресе —
  для «открыть в новой вкладке». Два вида, переключатель запоминается:
  - **«Таблица»**: курсы × недели семестра, в клетке — свои семинары недели
    значками; справа «Был» (процент) и «Макс.»; над таблицей карточки по всем
    курсам.
  - **«По неделям»**: одна неделя списком по дням (время, курс, семинар,
    преподаватель, аудитория, статус), стрелки ‹ › и «Текущая неделя».
- **Норма** — поле над таблицей, по умолчанию 75% — норма ЦУ
  (`DEFAULT_NORM` в `attendance_api.js`). Процент не ниже нормы — зелёный, в
  пределах 15 п.п. ниже — жёлтый, ещё ниже — красный. LMS норму не отдаёт,
  поэтому у курса с другой нормой её можно поменять вручную; она общая для
  сводной, колонки списка и страницы курса.
- **Контрольные.** Если в меню включено «Видеть предстоящие контрольные»,
  недели с контрольной по курсу помечены флажком, а в виде «По неделям» —
  предупреждение «семинары в эти дни лучше не пропускать». Расписание — общее
  `course-view/future_exams_api.js`.
- Названия курсов в таблице — кнопки: переход через щелчок по спрятанной
  родной строке (роутер Angular, без перезагрузки).

Цель метрики `attendance_summary_open` — открыта вкладка «Сводная».

## `attendance_course.js`

Страница курса `/learn/attendance/courses/{id}`. Под заголовком и выбором даты:

- «Мои семинары: был на X из Y (Z%)», сколько ждут отметки, сколько впереди и
  максимум;
- полоса всех своих семинаров семестра чипами «дд.мм день» с цветом статуса;
  в подсказке — время, преподаватель, аудитория;
- галочка **«Только мой семинар в таблице ниже»** (по умолчанию включена):
  прячет в родной таблице строки чужих групп — те, у которых значок
  «Записан» без класса `_participant`. Если своей пары в выбранный день нет,
  под полосой пишется, сколько строк скрыто, — иначе пустая таблица выглядит
  как «LMS ничего не отдала».

## Ключи `localStorage`

Все три чистит «Сбросить данные LMS» (`_shared/reset.js`).

| Ключ                            | Что                                                |
| ------------------------------- | -------------------------------------------------- |
| `culms.attendance.prefs`        | Вид сводной (`table` / `week`) и норма             |
| `culms.attendance.course.prefs` | Галочка «Только мой семинар»                       |
| `culms.attendance.cache.v1`     | Кеш дней: свои пары и отметки, дата запроса (`at`) |
