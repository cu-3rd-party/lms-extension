# Плагин `course-view` — страница курсов

**URL:** `/learn/courses/view` (список курсов, обзор конкретного курса)

Набор скриптов для улучшения работы со списком курсов и страницей отдельного курса.

---

## Файлы и их назначение

### `courses_fix.js`

Оркестратор виджетов страницы отдельного курса. Реагирует на SPA-навигацию и по
условию из настроек запускает виджеты из других файлов плагина.

**Как работает:**

1. Подписывается на `MutationObserver` за изменением URL (SPA-навигация): при
   переходе на страницу конкретного курса (`/view/(actual|archived)/{ID}`)
   запускает `processInvidualCoursePage()`.
2. При изменении ключевых настроек (`futureExamsViewToggle`, `courseOverviewTaskStatusToggle`, `futureExamsDisplayFormat`) перезагружает страницу.
3. По условию из `browser.storage.sync` запускает `viewFutureExams()`,
   `activateCourseOverviewTaskStatus()`, `activateCourseExporter()` и
   `activateCourseOverviewAutoscroll()` — сами виджеты реализованы в соответствующих файлах.

**Важно:** раньше здесь же жил «архиватор курсов» (кнопки архивации/разархивации,
`browser.storage.local.archivedCourseIds`, скрытие списка курсов через
`preload.js`/`preload.css` до его отработки) — убран целиком как нерабочий:
удалены `preload.js`, `preload.css` и вся связанная логика из этого файла и
из `content_scripts` в `manifest.config.js`. Функционал drag-and-drop был
удалён ранее, так как LMS официально поддерживает перетаскивание курсов через
`cdkDrag`.

**Взаимодействие со страницей:**

- Читает DOM: `location.href`/`location.pathname` для определения текущей страницы
- Хранилище: `browser.storage.sync` (настройки виджетов)

### `course_cards.js` + `course_cards.css`

Возвращает старый дизайн карточек курсов (обложка + подпись снизу), позволяет
поставить на обложку свою картинку и убрать курс в собственный архив. Все
настройки живут в попапе в отдельном разделе «Карточки курсов»; сам дизайн
включается тумблером «Старый дизайн карточек» (`oldCoursesDesignToggle` в
`browser.storage.sync`).

**Почему написано заново:** до редизайна LMS обложкой был `img.course-icon`, и
старый `course_card_image_replacer.js` просто подменял ему `src`. После редизайна
карточка (`cu-course-card`) — это текстовая плашка с категорией и названием, а
никакого `img.course-icon` в DOM больше нет, поэтому подменять стало нечего.
Теперь обложка рисуется поверх нативной карточки.

**Как работает:**

1. Работает только на списке курсов. Список живёт по `/view/(actual|archived)`
   плюс сегмент вкладки фильтра (`/actual/all`, `/actual/required`, …); страница
   отдельного курса отличается тем, что этот сегмент — числовой id
   (`/actual/1245`), и там плагин не запускается.
2. Один раз тянет `GET /api/micro-lms/courses/student?...` и строит карту
   «название курса → `{ id, category }`». `id` используется ключом в хранилище
   иконок — в том же формате, в котором их писала старая версия плагина
   (`{ "969": "data:..." }`), так что ранее сохранённые картинки подхватываются.
   Если API недоступен, ключом становится `name:<название>`.
3. Внутрь каждой `cu-course-card` добавляет `div.culms-cover`, а в `li` —
   подпись `div.culms-old-title`. Родное содержимое карточки не удаляется, а
   скрывается через CSS: удаление ломает перерисовку Angular.
4. Если своя картинка не задана, на обложке показывается заглушка — иконка
   категории и её название на фирменном цвете категории (палитра совпадает с
   `.course-card.<категория>` в `dark-theme.css`).
5. Кнопки редактора живут в `div.culms-card-actions` на самой `li`, а не на
   обложке: переименовывать и архивировать курсы нужно и на родном дизайне LMS,
   когда обложки выключены. Поэтому режим редактора сам по себе обложки больше
   **не** включает — они зависят только от тумблера. Кнопки: **✎** картинка,
   **✕** убрать свою картинку (только если она задана), **✏** переименовать
   (скрыта, если id курса не определился), **⇩** в архив.
6. Редактировать карточки можно только в **режиме редактора** — на списке курсов
   с `?customCardEditor=true` (кнопка «Открыть редактор карточек» в попапе;
   старый `?customIconEditor=true` тоже принимается, чтобы не ломать закладки).
   Вне его никаких кнопок на обложке нет и клик по карточке просто открывает
   курс. В редакторе карточки обводятся пунктиром, появляются **✎** (выбрать
   картинку), **✕** (убрать свою; только если картинка задана) и **⇩** (убрать
   курс в архив), клик по самой обложке тоже открывает выбор файла, а переход на
   курс заблокирован. Снизу висит панель с кнопкой «Готово»: она убирает параметр
   из URL через `history.replaceState`, без перезагрузки страницы.
7. Картинка перед сохранением ужимается до **480 px** по длинной стороне
   (`MAX_ICON_SIDE`) и пережимается в WebP (JPEG как фолбэк) — иначе квота
   `storage.local` кончается за несколько курсов. Гифки до 512 КБ сохраняются
   как есть, чтобы не потерять анимацию.

   480 px — с запасом под экран: обложка занимает ~200 CSS px по длинной
   стороне, то есть даже при DPR 2 нужно не больше ~430 px. Раньше здесь было
   800 px — это ~94 КБ на курс против ~53 КБ, то есть ~1,2 МБ против ~690 КБ на
   тринадцати курсах. Плата за это — мягче картинка при `stickerScale` больше
   ~200 %.

8. Картинки, сохранённые прошлой версией (до 800 px), **ужимаются один раз** при
   заходе на список курсов: `shrinkStoredIcons()` запускается после первой
   отрисовки, в `requestIdleCallback`, и перекодирует только то, что больше
   лимита, — то есть второй раз проход ничего не находит. Гифки не трогает.
   Без этого уменьшение `MAX_ICON_SIDE` помогло бы только новым картинкам.
9. Как картинка вписывается в обложку, задаётся общими настройками из попапа:
   `stickerObjectFit` (`cover` / `contain` / `fill` / `scale-down`) кладётся в
   `object-fit`, а `stickerScale` (25–400 %) — в `transform: scale()`. Значения
   нормализуются при чтении, так что мусор в хранилище откатывается к `cover`
   и 100 %. В старой версии в этом же ключе лежало значение `fit`, которое не
   является валидным `object-fit` и молча игнорировалось браузером — теперь оно
   тоже нормализуется в `cover`.
10. **Архив — целиком наш.** LMS архивирует курсы сама (`state=archived`), и
    повлиять на это из расширения нельзя, поэтому «убранный в архив» курс просто
    получает класс `culms-archived-item` (`display: none`) в списке актуальных.
    Селектор скрытия в CSS намеренно длиннее необходимого
    (`ul.course-list.culms-old-design > li.course-list__item.culms-archived-item`):
    правило старого дизайна задаёт `display: flex` селектором со специфичностью
    (0,3,2), и короткий вариант (0,2,1) ему проигрывал при одинаковом
    `!important` — скрытые карточки оставались пустыми ячейками грида.
    Список ключей лежит в `browser.storage.local.archivedCourseIds` — тот же
    ключ, что использовал удалённый архиватор из `courses_fix.js`.
    Скрытие работает **независимо от тумблера старого дизайна**: иначе курсы,
    убранные в архив, молча возвращались бы при выключении дизайна. Кнопка **⇩**
    при этом живёт на обложке, то есть доступна только в режиме редактора.
11. На странице архивных курсов (`/view/archived`) свои курсы вставляются
    **строками прямо в нативную таблицу** (`tr.culms-archived-row` в начало
    `cu-archive-courses tbody`), у каждой — кнопка «Вернуть». Строка собирается
    клонированием нативной: так сохраняются `_ngcontent-*`, без которых
    Angular-стили таблицы к ней не применятся; проверено, что левые границы
    ячеек и высота строки совпадают с нативными. Кнопка кладётся в последнюю
    ячейку внутрь флекс-обёртки `.culms-archived-row__cell` — менять `display`
    у самой `td` нельзя, она перестанет быть ячейкой таблицы и развалит колонки.
    Названия и категории берутся из `state=published`-ответа: спрятанные курсы
    остаются активными, и в `state=archived` их нет. Иконку бейджа берём из
    `CATEGORY_ICONS`; если категории там нет, иконка убирается и остаётся подпись.

    Строки показываются **только на первой странице** — в нативную пагинацию они
    не входят («1–20 из 31» их не считает), и без проверки один и тот же курс
    повторялся бы на каждой странице. Признак первой страницы — отключённая
    кнопка «Предыдущая страница». Angular пересобирает таблицу при пагинации и
    поиске, поэтому строки восстанавливаются наблюдателем по подписи
    `tbody.dataset.culmsSignature`.

12. **Раскладка ставится до сетевого запроса.** Классы сетки (`culms-old-design`
    и соседние) навешиваются в `renderActualList()` сразу, а покарточная часть
    (обложки, ключи, скрытие архивных) выполняется ниже, после `metaLoaded`.
    Раньше `renderCurrentPage()` целиком выходил по `!metaLoaded`, а `apply()`
    ждал `loadCourseMeta()` — список около 220 мс (время ответа API) стоял с
    родной плотной сеткой LMS (`gap: 4px`), а затем скачком разъезжался.
13. **Картинки читаются отдельным запросом к хранилищу.** В `init()` сначала
    уходит `storage.local.get('courseIcons')`, и на нём ничего не ждёт: архив,
    соответствие id→курс и настройки приезжают своим, лёгким `get`, так что
    скрытие архивных курсов не зависит от веса картинок. Раньше всё читалось
    одним `get`, и в Firefox — где `storage.local` живёт в IndexedDB и ходит
    через IPC со structured clone — заархивированные карточки успевали мелькнуть.

    При этом сам **старый дизайн включается только вместе с картинками**:
    `showCovers = enabled && iconsLoaded`. Если навесить сетку раньше, родное
    содержимое карточки уже скрыто (`cu-course-card > *:not(.culms-cover)`), а
    обложек ещё нет — на месте курсов будут пустые прямоугольники. Поэтому до
    прихода картинок на экране остаётся родной дизайн LMS, а переключение
    происходит одним шагом. Если запрос картинок упал, `iconsLoaded` всё равно
    выставляется — иначе обложки не появились бы вовсе.

14. Соответствие id→курс кешируется в `browser.storage.local.courseMetaCache`
    (~1 КБ) и поднимается в `init()` до сети. Без кеша первая отрисовка знала бы
    только названия, и заархивированные карточки успевали мелькнуть на экране;
    актуальные данные приходят следом и перерисовывают список. Пустой или
    битый кеш просто не применяется — `applyCourseMeta()` возвращает `false`,
    и работает обычный путь через сеть.
15. **`transition: none` на карточке — обязательно.** У нативной
    `cu-course-card` LMS объявляет `transition: 0.3s ease-in-out` без указания
    свойства, то есть `all`. Мы задаём карточке `width: 100%` и
    `aspect-ratio: 16 / 9` уже после того, как отработала родная раскладка, —
    и браузер анимирует этот переход родным правилом LMS. На практике при
    открытии списка и при смене вкладки фильтра карточка появлялась ~258px и
    примерно треть секунды ужималась до 198px, выглядело как анимация
    появления. Собственный ховер-переход живёт на `.culms-cover`
    (`transform 0.2s`) и этим не задет.
16. Критичные для раскладки свойства обложки (`position: absolute`, `inset`,
    `overflow`) дублируются инлайном при создании элемента. В CSS они объявлены
    с `!important`, так что конфликта нет, зато обложка не «растекается» на всю
    строку, если стиль плагина почему-то приедет позже скрипта (порядок
    внедрения см. в `src/plugins/README.md`).
17. `MutationObserver` перерисовывает обложки после перерисовок Angular (смена
    вкладки фильтра, drag-and-drop) — отрисовка идемпотентна. При уходе со
    списка и при выключении тумблера всё добавленное удаляется.

**Взаимодействие со страницей:**

- Читает DOM: `ul.course-list`, `li.course-list__item`, `cu-course-card`,
  `.course-name`, `.category-icon`, `.category-name`, `cu-archive-courses`
- Вставляет: `div.culms-cover` внутрь карточки, `div.culms-old-title` в `li`
- Вставляет: панель редактора `#culms-card-editor-bar` в `document.body`
- Вставляет: строки `tr.culms-archived-row` в нативную таблицу архивных курсов
- Хранилище: `browser.storage.sync` (`oldCoursesDesignToggle`, `themeEnabled`,
  `stickerObjectFit`, `stickerScale`), `browser.storage.local` (`courseIcons` —
  отдельным запросом, `archivedCourseIds`, `courseMetaCache`)
- Названия курсов: ключ иконки и архива считается по **оригинальному** названию
  через `window.cuLmsCourseNames.originalFor()`, а подпись под обложкой
  показывает то, что видит пользователь. Переименование выполняет
  `_shared/course_names.js`, здесь только вызывается `setOverride()`.
- Fetch: `/api/micro-lms/courses/student` (список курсов с id и категориями)

### `course_overview_task_status.js`

Отображает статус задачи прямо в раскрывающемся аккордеоне курса.

**Как работает:**

1. Извлекает `courseId` из URL (`/view/actual/123` или `/view/archived/123`).
2. Параллельно запрашивает три API-эндпоинта LMS:
   - `/api/micro-lms/courses/{id}/exercises` — список упражнений
   - `/api/micro-lms/courses/{id}/student-performance` — успеваемость
   - `/api/micro-lms/tasks/student` — список задач с датами
3. Строит карту `longreadId → статус последней задачи`.
4. Для каждого `tui-accordion-item` в `cu-course-overview` ищет соответствующий лонгрид и вставляет иконку статуса (✅ сдано / ❌ просрочено / ⏩ скип / 🔄 доработка / ⏳ ожидает).

**Взаимодействие со страницей:**

- Читает DOM: `cu-course-overview`, `tui-accordion-item`
- Вставляет: иконки/чипы статуса рядом с каждой темой аккордеона
- Fetch: 3 API-запроса к LMS

### `course_overview_autoscroll.js`

Автоматически прокручивает к последней теме курса при открытии.

**Как работает:**

1. Ждёт появления `cu-course-overview` (через `waitForElement` с таймаутом 10 сек).
2. Берёт все `tui-accordion-item`, которые **не** являются будущими экзаменами (`data-item-type !== 'future-exam'`).
3. Прокручивает к последнему из них (`scrollIntoView({ behavior: 'smooth', block: 'center' })`).
4. Кликает по нему, чтобы раскрыть.

**Взаимодействие со страницей:**

- Читает DOM: `cu-course-overview`, `tui-accordion-item`
- Вызывает: `scrollIntoView()`, `button.click()`

### `course_friends_list.js`

Виджет с информацией о том, кто из друзей также записан на открытый курс.

**Как работает:**

1. Читает список друзей из `localStorage` (`cu_friends_list`).
2. Запрашивает у LMS API данные о курсах для каждого друга.
3. Нормализует названия курсов и сравнивает с текущим (учитывает разные форматы написания, C++, etc.).
4. Создаёт плавающий виджет (`<div id="cu-friends-floating-widget">`) в правом нижнем углу страницы.
5. В виджете отображается список друзей: тех, кто на том же курсе — в начале, остальные — ниже.
6. Виджет поддерживает светлую / тёмную / OLED темы.

**Взаимодействие со страницей:**

- Вставляет: `<div>` виджет в `document.body`
- Читает: `localStorage` (список друзей), `browser.storage.sync` (тема)
- Fetch: API LMS для получения курсов друзей

### `future_exams_view.js`

Показывает в аккордеоне курса предстоящие контрольные работы и экзамены.

**Как работает:**

1. Тянет расписание контрольных (`GET /api/schedule`) и дату первой недели
   семестра (`GET /api/config`) с отдельного сервера
   [lms-future-exams-backend](https://github.com/cu-3rd-party/lms-future-exams-backend) —
   там же их правят вручную через защищённую паролем страницу `/admin`, без
   релиза расширения. Раньше список и дата первой недели были захардкожены
   прямо в этом файле (объект `schedule` и `new Date(currentYear, 1, 2)`) —
   из-за чего в начале осеннего семестра номера недель в формате «неделя N»
   съезжали (продолжали считаться от февральской даты).
2. Кэширует оба ответа в `browser.storage.local` на 30 минут
   (`FUTURE_EXAMS_CACHE_TTL_MS`); при недоступности сервера отдаёт последний
   закэшированный вариант.
3. Сам запрос идёт не напрямую `fetch()` из этого файла, а через сообщение
   `FETCH_JSON` в background (`src/background.ts`): в Firefox content-скрипты
   не получают CORS-обход из `host_permissions`, в отличие от Chrome, и
   прямой кросс-доменный fetch падал с «CORS request did not succeed» даже
   при `Access-Control-Allow-Origin: *` на сервере. У background-скрипта
   такого ограничения нет ни в Chrome, ни в Firefox.
4. Находит текущий курс по названию в DOM.
5. Добавляет специальные `tui-accordion-item` с типом `future-exam` и датами в стиль лонгридов.
6. Поддерживает два формата отображения: `full` (название + дата) и `compact` (только дата).

**Взаимодействие со страницей:**

- Читает DOM: `cu-course-overview`, название курса
- Вставляет: `tui-accordion-item` элементы в аккордеон
- Fetch: `FUTURE_EXAMS_BACKEND_URL` (`https://lms.exams.cu3rd.ru`) +
  `/api/schedule`, `/api/config` — через `browser.runtime.sendMessage({ action: 'FETCH_JSON' })`
  в background, не напрямую (см. п. 3 выше); см. также `host_permissions` в
  `manifest.config.js`
- Хранилище: `browser.storage.local` (`futureExamsScheduleCache`,
  `futureExamsScheduleCacheTimestamp`, `futureExamsConfigCache`,
  `futureExamsConfigCacheTimestamp`)

### `course_exporter.js`

Виджет для выгрузки материалов и задач курса в форматах ZIP и PDF.

**Важно:** Виджет отображается только на страницах активных курсов (`/learn/courses/view/actual/{ID}`), на архивированных курсах не показывается.

**Как работает:**

1. Добавляет виджет «Экспорт материалов» в боковую панель страницы курса, стилизованный под нативные виджеты LMS.
2. Предоставляет три кнопки:
   - **ZIP (всё + ДЗ):** Сохраняет иерархическую структуру (Темы -> Лонгриды -> Файлы) и включает решения домашних заданий.
   - **ZIP (без ДЗ):** Собирает все файлы «плоским» списком (все в корне) без решений ДЗ.
   - **PDF (без ДЗ):** Находит все PDF-материалы курса и склеивает их в один документ.
3. Отображает прогресс выполнения (сканирование, скачивание, сборка) в процентах прямо на кнопках.
4. Автоматически адаптируется под тему оформления (Light, Dark, OLED) и следит за её сменой в реальном времени.
5. Интегрирован с SPA-навигацией: виджет пересоздается при переходе между курсами и сохраняет работоспособность.

**Взаимодействие со страницей:**

- Читает DOM: `cu-course-overview h1.page-title`, `cu-widgets-panel`
- Вставляет: Виджет в `cu-widgets-panel` с использованием нативных CSS-классов (`header`, `header__title`).
- Fetch: Запросы к LMS API для сбора структуры, материалов и скачивания файлов.
- Библиотеки: `fflate` (ZIP), `pdf-lib` (PDF).
