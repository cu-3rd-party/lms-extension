# Плагин `theme-editor` — редактор своей темы

**URL:** страница расширения `plugins/theme-editor/theme-editor.html` (открывается
отдельной вкладкой)

Полноценный редактор палитры LMS: список подписанных цветовых переменных,
свой CSS с колорпикером по месту и пипетка, которая разбирает выбранный элемент
страницы. Это про цвета интерфейса — обложки курсов и логотип живут отдельно
(`_shared/custom_logo.js`, `course-view/course_cards.js`).

---

## Откуда берётся и куда пишет

Редактор ничего не применяет сам. Он пишет три ключа, а стиль на страницах
собирает контент-скрипт [`_shared/custom_theme.js`](../_shared/custom_theme.js):

| Ключ                | Хранилище | Что                                          |
| ------------------- | --------- | -------------------------------------------- |
| `customThemeToggle` | `sync`    | Включена ли своя тема                        |
| `customThemeVars`   | `local`   | `{ '--accent': '#ff0000', … }`               |
| `customThemeCss`    | `local`   | Произвольный CSS                             |
| `customThemeName`   | `local`   | Название темы — попадает в файл при экспорте |

Так сделано ради «живого» редактирования: `storage.onChanged` приходит во все
вкладки сразу, поэтому правка видна и в той вкладке, где редактор не открыт.
Кнопки «Сохранить» для палитры поэтому нет — есть задержка в 150 мс, чтобы
ползунок колорпикера не порождал сотню записей в секунду.

Список переменных и сборка итогового CSS — в
[`_shared/theme_tokens.js`](../_shared/theme_tokens.js), общем для редактора и
контент-скрипта.

## Вкладка рядом, пипетка на странице

Редактор всегда открывается **отдельной вкладкой** (`OPEN_THEME_EDITOR` в
`background.ts`; вторую вкладку не заводим — обе писали бы одни ключи и
перетирали правки друг друга). Поверх страницы он висел оверлеем и закрывал
как раз то, что красишь.

Чужой DOM из вкладки расширения не виден, поэтому элементы разбирает
контент-скрипт [`_shared/theme_editor_host.js`](../_shared/theme_editor_host.js)
на самой странице LMS. Пока вкладка редактора открыта, там взведена пипетка:
**ПКМ по элементу** присылает сюда его цвета. Правая кнопка, а не левая,
потому что по странице в это время надо продолжать ходить — доходить до того
самого элемента, который не так покрашен.

Связь — через `storage.local`, общего окна у вкладок нет, а
`storage.onChanged` и так приходит во все сразу. Ключи служебные, в профиль
темы не попадают (группа `private` в реестре):

| Ключ                 | Кто пишет  | Что                                           |
| -------------------- | ---------- | --------------------------------------------- |
| `themePickerActive`  | редактор   | Вкладка открыта, пипетку можно взводить       |
| `themePageValues`    | страница   | Значения переменных каталога на этой странице |
| `themePickResult`    | страница   | Разбор последнего элемента (+ `at` — когда)   |
| `themeEditorTabId`   | background | Какую вкладку поднимать вместо открытия новой |
| `themeSourceRequest` | редактор   | «Покажи всё, что красишь»                     |
| `themeSourceDump`    | страница   | Тексты всех наших `<style>` (удаляется сразу) |

Пипетка выключается тумблером в шапке редактора, клавишей Esc на самой
странице и автоматически, когда вкладку редактора закрывают (`pagehide`) —
иначе на странице навсегда осталось бы отобранное контекстное меню.

## Вкладки

### Палитра

Переменные из каталога, сгруппированные по происхождению (палитра LMS,
компоненты Taiga UI, наша тёмная тема). У каждой — подпись, где она видна,
имя переменной и текущее значение с пометкой, откуда оно взято: своё, со
страницы или из тёмной темы.

Рядом с колорпикером всегда есть текстовое поле: `rgba(...)` и `var(...)` в
`<input type="color">` не помещаются, а они в палитре LMS встречаются. Поле
краснеет, если браузер не признал значение цветом, и такое значение не
сохраняется: в CSS оно бы молча пропало, а в файл темы уехало бы мусором.

### styles.css

Выпадающий список наверху переключает, что показано.

**Моя тема** — редактируемый файл, тот самый, что применяется поверх LMS.

**Все переменные плагина с подписями** — справка: все 67 переменных каталога,
сгруппированные и подписанные, со значениями, которые сейчас стоят на
странице. Пипеткой находится не всё, а тут список целиком и его можно искать
глазами.

**Стили плагина на странице** — выгрузка живых `<style>` с открытой вкладки
LMS: тёмная тема целиком, OLED-надстройка, фон, логотип, ваша тема. Это то,
что реально применено, а не файл из репозитория; нужно, когда плагин красит
что-то правилом, а не переменной, и надо увидеть селектор.

Обе справки — только для чтения, с поиском по тексту и кнопкой «Скопировать в
мою тему»: выделили правило — оно уехало в редактируемый файл (без выделения
уедет весь текст). Своя тема применяется после этих стилей, поэтому
скопированное правило их перебивает. У выгрузки в шестнадцать тысяч строк поля
с квадратиками не рисуются — иначе вкладка подвисала бы на каждом
переключении.

В своём файле три способа править цвет:

1. **Квадратики на полях.** Слева от каждой строки рисуются цвета, найденные в
   ней; клик открывает колорпикер и меняет ровно это вхождение.
2. **Цвет под курсором.** Если каретка стоит внутри цвета, в тулбаре
   появляется колорпикер, который правит его по месту.
3. Руками, как в обычном текстовом поле.

Поля и текст выровнены построчно, поэтому у них одинаковый моноширинный шрифт,
фиксированный `line-height` и выключенный перенос строк.

Проверка одна — баланс скобок: браузер молча выбрасывает непонятные правила, а
вот незакрытая скобка съедает весь остаток файла, и это как раз тот случай,
когда непонятно, «почему ничего не работает».

### Элемент

Заполняется после ПКМ по элементу на вкладке LMS. Показывает:

- селектор (его можно поправить руками) и сколько элементов он задевает;
- цвета элемента — только осмысленные: `border-color` без рамки, `fill` у
  не-SVG и `outline-color` без обводки в список не попадают;
- **переменные каталога, чей цвет совпал с цветом элемента** — главный ответ на
  вопрос «что крутить, чтобы поменялось вот это». Кнопка «Править» ведёт к этой
  переменной в палитре.

Правка цвета отсюда дописывает правило в блок `/* правила из пипетки */` в
конце `styles.css`. Повторная правка того же свойства заменяет значение, а не
плодит дубли.

## Файлов тут нет

Экспорт и импорт тем живут **в меню плагина** (раздел «Выбор темы»): редактор
правит текущую тему, а файлами заведует меню — там же, где выгрузка остальных
настроек, и тем же механизмом профилей (`_shared/settings_registry.js`, вид
`theme`, см. [`PROFILE-FORMAT.md`](../../../PROFILE-FORMAT.md)). Название темы
задаётся там же и показывается в шапке редактора.

Своя кнопка «Скачать» на вкладке styles.css осталась — она сохраняет открытый
текст как обычный `.css`, к обмену темами отношения не имеет.
