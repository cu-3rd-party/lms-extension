# Плагин `longreads` — страница задания

**URL:** `/longreads/...` (страница конкретного задания/лонгрида)

Набор скриптов для улучшения работы на странице отдельного задания.

---

## Файлы и их назначение

### `homework_weight_fix.js`

Отображает вес задания в итоговой оценке курса.

**Как работает:**

1. Извлекает `longreadId` из URL (`/longreads/123`).
2. Запрашивает `/api/micro-lms/longreads/{id}/materials?limit=10000`.
3. Ищет в ответе поле `estimation.activity.weight`.
4. Ждёт появления `ul.task-info` в DOM.
5. Клонирует элемент «Оценка» из списка метаинформации, меняет в нём иконку и текст на «Вес: XX%» и вставляет рядом.

Также содержит логику для отображения количества штрафных дней (late days), если они применимы к заданию.

**Взаимодействие со страницей:**

- Читает DOM: `ul.task-info`, `.task-info__item`
- Вставляет: новый `<li>` с весом задания
- Fetch: `/api/micro-lms/longreads/{id}/materials`

### `instant_doc_view_fix.js`

Позволяет просматривать вложенные файлы и изображения в модальном окне прямо на странице задания.

**Как работает:**

1. Создаёт скрытый модальный оверлей (`<div class="cu-lms-modal-overlay">`) с `<img>` или `<iframe>` внутри.
2. `MutationObserver` отслеживает появление вложений (ссылок с атрибутом `download`, изображений, ссылок на документы).
3. При клике на вложение перехватывает навигацию (`e.preventDefault()`), открывает модальное окно и загружает файл внутрь него.
4. Закрытие — по клику на оверлей или кнопку ✕.
5. Анимация появления через CSS `opacity` и `transform: scale`.

**Взаимодействие со страницей:**

- Вставляет: `<div>` модального окна в `document.body`, `<style>` анимации в `<head>`
- Перехватывает: клики по вложениям задания
- Fetch-запросов не делает

### `rename_hw.js`

Автоматически переименовывает файл перед загрузкой на сервер по заданному шаблону.

**Как работает:**

1. Читает настройки из `browser.storage.sync`: флаг `autoRenameEnabled`, шаблон `autoRenameTemplate`.
2. Перехватывает `change`-событие на `<input type="file">` через `MutationObserver` (ждёт появления поля).
3. Получает имя и фамилию студента из API (`/api/account/me`) и кэширует.
4. Определяет номер недели:
   - Сначала из элементов навигации (текст «неделя N»)
   - Затем из заголовков `<h4>` (текст «ДЗ N»)
   - В крайнем случае — вычисляет по последней дате из истории задачи
5. Создаёт `File` объект с новым именем из шаблона (например: `Иванов_неделя5.pdf`) через `DataTransfer`.
6. Подставляет переименованный файл в `input.files`.

**Поддерживаемые шаблоны:**

- `dz_fi` → `dz_Фамилия_Имя_неделяN.ext`
- `fi_dz` → `Фамилия_Имя_dz_N.ext`
- и другие, заданные в попапе

**Взаимодействие со страницей:**

- Читает DOM: `<input type="file">`, навигация курса, история задач
- Модифицирует: `input.files` (через DataTransfer API)
- Fetch: `/api/account/me`

### `task_status_adaptation.js`

Отображает кастомные статусы («Метод скипа», «Доработка») прямо на странице задания.

**Как работает:**

1. Загружает список задач студента с API (`/api/micro-lms/tasks/student`) один раз и кэширует.
2. `MutationObserver` ждёт появления элементов `cu-student-task` на странице.
3. Для каждого задания:
   - Проверяет, входит ли оно в `localStorage`-сет скипнутых задач (`cu.lms.skipped-tasks`).
   - Проверяет API-данные: если задача отклонена и дата rejectAt позже submitAt — значит это «Доработка».
4. Заменяет или дополняет стандартный чип статуса (`tui-chip`) кастомным.

**Взаимодействие со страницей:**

- Читает DOM: `cu-student-task`, `.task-name`, `tui-chip`
- Модифицирует: текст и стиль чипа статуса
- Fetch: `/api/micro-lms/tasks/student`
- Хранилище: `localStorage` (cu.lms.skipped-tasks)

### `pdf_dark_theme.js` + `pdf_viewer.html` / `pdf_viewer.js`

Открывает PDF-вложения лонгрида в тёмной версии, перекрашивая их «на лету» прямо в браузере. Фича основана на алгоритме из `3rd-pdf` и работает исключительно локально.

Фича раскидана по двум местам:

| Файл                                | Где исполняется                     | Что делает                                    |
| ----------------------------------- | ----------------------------------- | --------------------------------------------- |
| `pdf_dark_theme.js`                 | content-скрипт на странице лонгрида | ловит клик по PDF, достаёт ссылку на оригинал |
| `pdf_viewer.html` + `pdf_viewer.js` | отдельная страница расширения       | скачивает, перекрашивает и показывает         |

**Как работает:**

1. `pdf_dark_theme.js` читает настройку `darkPdfEnabled` (`browser.storage.sync`) и следит за её изменениями. Основная тёмная тема (`themeEnabled`) не требуется.
2. Вешает один общий обработчик клика на `document` в фазе перехвата (`{ capture: true }`). Для `a.file`, у которого `.t-type` равен `.pdf`, вызывает `preventDefault` + `stopImmediatePropagation`, перехватывая клик до Angular и до `instant_doc_view_fix.js`.
3. Запрашивает через API LMS (`/api/micro-lms/longreads/{id}/materials`, затем `/api/micro-lms/content/download-link`) оригинальную ссылку на скачивание (Yandex Cloud S3).
4. Шлёт в background сообщение `OPEN_PDF_VIEWER` со ссылкой и именем файла. Background открывает `browser.tabs.create` со страницей `plugins/longreads/pdf_viewer.html?src=...&name=...`.
5. `pdf_viewer.js` скачивает оригинальный PDF, декомпрессирует потоки (`fflate`), парсит документ (`pdf-lib`) и переписывает операторы цвета (`rg/RG`, `k/K`, `g/G`, `sc/scn`) в контент-стримах страниц и Form XObject'ах, заменяя светлые цвета на тёмные аналоги, плюс добавляет тёмную заливку страницы.
6. Создаёт Blob-URL **в контексте самой страницы** и показывает результат в `<iframe>`; имя файла уходит в `document.title`.
7. Если файл не найден в API материалов (например, это решение студента), обработка отменяется и клик повторяется нативно через флаг `data-cu-pdf-dark-ignore`. Туда же уходит любая ошибка в обработчике — лучше отдать обычный светлый PDF, чем ничего.

**Взаимодействие со страницей:**

- Читает DOM: элементы лонгрид-материалов, `.t-type`, `.t-name`
- Модифицирует: перехватывает клики по `a.file`
- Fetch:
  - `/api/micro-lms/longreads/{id}/materials` (или использует встроенный API расширения `window.__culmsLmsApi`)
  - `/api/micro-lms/content/download-link`
  - Скачивает оригинальный PDF с S3 (Yandex Cloud) — уже со страницы просмотра
- Хранилище: `browser.storage.sync` (`darkPdfEnabled`)
- Библиотеки: `pdf-lib` и `fflate` из `plugins/_shared/`, подключены тегами `<script>` в `pdf_viewer.html`

**⚠️ Почему просмотр — отдельная страница, а не всплывающее окно**

Раньше content-скрипт делал `window.open('', '_blank')` и рисовал в полученное окно через `win.document.write`. В Chromium это работало, **в Firefox вкладка навсегда оставалась на `about:blank`** — без спиннера и без ошибки: запись шла в чужой документ через Xray-обёртку, а свежий `about:blank` в Gecko ещё и перезатирается, когда доезжает его начальная загрузка. Вдобавок вся эта часть лежала вне `try/catch`, а обработчик `async` — исключение превращалось в тихий unhandled rejection.

Поэтому:

- **не возвращай обработку PDF в content-скрипт** и не рисуй ничего через `document.write`;
- вкладку открывает background через `tabs.create` — блокировщик всплывающих окон при этом не при чём, и ссылку можно спокойно дождаться до открытия вкладки;
- Blob-URL создаётся на самой странице просмотра: blob из контекста content-скрипта не всегда грузится встроенной смотрелкой;
- `pdf_viewer.js` намеренно **не использует extension API** — всё приходит из query-строки, пути относительные. Благодаря этому страницу можно поднять по http и прогнать в настоящем Firefox без расширения и без логина в ЛМС: `bunx playwright test tests/pdf-viewer-firefox.test.ts`.

**⚠️ Если у пользователя в браузере выключена встроенная смотрелка PDF** («всегда скачивать PDF»), `<iframe>` честно отрабатывает `load`, но остаётся пустым — определить это из скрипта нельзя. Раньше на этот случай всегда показывалась шапка с прямой ссылкой на blob («Открыть отдельно»); её убрали, так что теперь в этом сценарии пользователь просто увидит пустую вкладку.

**Сборка:** `pdf_viewer.html` и `pdf_viewer.js` перечислены в `web_accessible_resources` в `manifest.config.js`. Для этих файлов это не про доступ (страницу открывает само расширение), а единственный способ попасть в `dist/` — crxjs копирует ресурсы из WAR как есть, сохраняя путь. HTML при этом не проходит через Vite, поэтому в `pdf_viewer.js` нельзя использовать ESM-импорты.
