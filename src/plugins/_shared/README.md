# Плагин `_shared` — общие скрипты

**URL:** все страницы `https://my.centraluniversity.ru/`

Набор вспомогательных скриптов, которые загружаются на **каждой** странице LMS. Здесь живут глобальные утилиты и функции, от которых зависят остальные плагины.

---

## Файлы и их назначение

### `version_check.js`

Проверяет актуальность версии расширения.

**Как работает:**

1. При загрузке страницы делает запрос к GitHub Gist, где хранится `version.json` с актуальными версиями для каждого браузера.
2. Сравнивает версию из манифеста расширения (`browser.runtime.getManifest().version`) с удалённой.
3. Если установленная версия устарела — вставляет в шапку сайта (`ul.header__actions-list`) уведомление со ссылкой на страницу релизов GitHub.
4. Проверка повторяется каждые 30 секунд.

**Взаимодействие со страницей:**

- Читает DOM: `ul.header__actions-list`, `li[automation-id="header-action"]`
- Вставляет: клонированный `<li>` с красной ссылкой «Плагин устарел»

---

### `reset.js`

Позволяет сбросить данные расширения, сохранённые в `localStorage`.

**Как работает:**

- Подписывается на два канала сообщений:
  - `browser.runtime.onMessage` — от попапа расширения (action `RESET_LMS_LOCAL_STORAGE_FROM_POPUP`)
  - `window.addEventListener('message')` — от встроенного iframe-меню (action `RESET_LMS_LOCAL_STORAGE_IFRAME`)
- При получении команды удаляет ключи:
  - `cu.lms.actual-student-tasks-custom-filter`
  - `cu.lms.actual-student-tasks-filter`
  - `cu.lms.skipped-tasks`
  - `cu_friends_list`

**Взаимодействие со страницей:** только `localStorage`, DOM не трогает.

---

### `friends_tab.js`

Добавляет вкладку **«Друзья»** в главную навигацию.

**Как работает:**

1. Ждёт появления `tui-tabs` (навигационная панель).
2. Создаёт и вставляет ссылку `<a id="custom-friends-link">` рядом с остальными вкладками.
3. По клику открывает оверлей (`#friends-overlay`) поверх страницы с полноэкранным UI друзей.
4. UI содержит: список друзей, формы добавления/удаления, поиск по имени, отметку об общих курсах.
5. Список друзей хранится в `localStorage` (`cu_friends_list`).
6. Тема (светлая/тёмная/OLED) синхронизируется с настройками расширения через `chrome.storage.onChanged`.

**Взаимодействие со страницей:**

- Читает DOM: `tui-tabs`, `.header__tab-link`
- Вставляет: `<a>` во вкладки, `<div id="friends-overlay">` в `document.body`
- Делает fetch к API LMS для получения данных об однокурсниках

### `course_names.js`

Свои названия курсов по всей LMS. Включается тумблером «Свои названия курсов»
(`customCourseNamesToggle` в `browser.storage.sync`), сами названия лежат в
`browser.storage.local.courseNames` как `{ "<id курса>": "Название" }`.

Модуль общий, а не часть плагина карточек: курс упоминается ещё в таблице
заданий, крошках, заголовке страницы курса, таблице архивных курсов и в
ведомостях (`/learn/reports/student-performance/...`).

**Как работает:**

1. Тянет список курсов и строит соответствие «id → настоящее название», из него
   — прямую и обратную карты названий.
2. Подменяет текст только в точечном списке селекторов (`.course-name`,
   `.task-table__course-name`, `td.name-cell`, `.breadcrumbs__item`,
   `tui-breadcrumbs a`, `h1.page-title`, `h1.course-learning__title`,
   `a.report-card h4`, `cu-student-course-performance h1.title`,
   `tui-multi-select-option span` и `.cu-filter-value__first` — опции и
   свёрнутый чип фильтра «Курс» в списке заданий, а также
   `.culms-exams-dashboard__course-name` — курсы в дэшборде контрольных под
   списком курсов: он пишет туда настоящее название, а своё подставляет этот
   модуль, как и в самом списке). Крошки берём все, а не
   только последнюю: внутри темы и урока курс оказывается средним звеном
   («Обучение › Мои курсы › Курс › Тема › Урок»). Списком селекторов, а не
   обходом всего документа: иначе подмена залезла бы в произвольный текст, где
   название курса встретилось случайно.

   Помимо видимых крошек берём и `tui-breadcrumbs a`: Taiga держит рядом
   невидимую копию крошек, по которой меряет, влезают ли они в строку, и из
   неё же собирает выпадающий список, когда не влезают.

   **Ведомости.** Список `/learn/reports/student-performance/{actual,archived}/...`
   вёрстка отдаёт по ширине окна: на обычном экране это таблица
   (`tr.course-row > td.name-cell`), и только на узком — карточки
   (`a.report-card h4`). Поэтому в списке два селектора, а не один: по одним
   карточкам подмена не работала бы ни у кого, кроме как в узком окне.
   `cu-student-course-performance h1.title` — заголовок самой ведомости и её
   вкладки «Активность», он одинаковый в обоих режимах. Переход по строке идёт
   по id курса, так что подмена текста на навигацию не влияет, а плагины из
   `statements/` названия курсов из DOM не читают.

   `td.name-cell` покрывает заодно и таблицу архивных курсов
   (`/learn/courses/view/archived`), где раньше стоял отдельный селектор
   `cu-archive-courses .name-cell` — и не срабатывал, см. следующий пункт.

   Опции фильтра рисует сама LMS — `courses/tasks_fix.js` подменяет список не
   всегда, поэтому полагаться только на него нельзя, и селектор покрывает оба
   варианта.

3. Рядом с подменённым текстом кладёт `data-culms-orig-name` (оригинал) и
   `data-culms-shown-name` (то, что записали мы).
4. Работает **по текстовым узлам**, а не через `textContent`, и обходит их
   вглубь (`TreeWalker`), а не только прямых детей элемента: LMS часто
   заворачивает название в служебный `span` — например
   `td.name-cell > span.limited-lines-text` в таблицах курсов и ведомостей. По
   прямым детям такая ячейка выглядит пустой, и подмена молча не срабатывает;
   именно на этом селектор `cu-archive-courses .name-cell` не работал с самого
   начала. Причин работать по узлам, а не по `textContent`, две:
   - название может быть лишь частью содержимого: в свёрнутом чипе фильтра
     лежат два отдельных текстовых узла — «Курс: » и само название, — и
     сравнение всего текста элемента не дало бы совпадения (а перезапись
     затёрла бы подпись);
   - в разметке Angular рядом с текстом лежат комментарии-якоря `<!---->`
     (например, внутри опции фильтра), и перезапись `textContent` их удаляет —
     после этого Angular не может обновлять такой узел.

**Почему два атрибута.** Узлы принадлежат Angular и переиспользуются между
разделами. Возвращать оригинал можно, только если на экране всё ещё ровно наша
подстановка (`data-culms-shown-name`), иначе запись затрёт уже отрисованный
заголовок другого раздела — та же ловушка, на которой раньше ломались крошки в
`cu-clubs.js`.

**Почему подмена синхронная.** Колбэк `MutationObserver` — микрозадача: он
выполняется в том же таске, что и сама мутация, то есть до шага отрисовки кадра.
Поэтому `applyAll()` вызывается прямо в колбэке, без откладывания. Любой перенос
в следующий таск (`setTimeout`) или кадр (`requestAnimationFrame`) означает, что
браузер успевает нарисовать родное название, и пользователь видит, как оно
меняется у него на глазах. Мутации приходят пачкой на таск, так что лишних
проходов синхронный вызов не создаёт.

Отложенный вариант тут был дважды, и оба раза неудачно: `requestAnimationFrame`
вдобавок не приходит вовсе в фоновой вкладке (флаг «проход запланирован»
остаётся взведённым, и последующие мутации теряются), а `setTimeout` давал
видимое переименование.

**Соответствие id → название кешируется** в `browser.storage.local.courseMetaCache`
(тот же ключ и формат, что у `course-view/course_cards.js` — список курсов один
и тот же, и прогретый одним модулем кеш экономит запрос другому). В `init()`
кеш поднимается до сети, иначе первая подмена ждала бы ответ API и LMS успевала
отрисовать родные названия. Свежий список приходит следом и поправляет
расхождения.

**Публичное API `window.cuLmsCourseNames`** — им обязаны пользоваться все, кто
завязан на настоящее название, иначе переименование ломает функциональность:

| Метод                                                   | Зачем                                                   |
| ------------------------------------------------------- | ------------------------------------------------------- |
| `originalFor(el, fallback)`                             | оригинал для элемента (из атрибута или обратной картой) |
| `toOriginal(text)` / `toDisplay(name)`                  | преобразование названий в обе стороны                   |
| `getOriginalById(courseId)`                             | настоящее название по id курса                          |
| `setOverride(courseId, name)` / `getOverride(courseId)` | запись и чтение переименования                          |
| `ready`                                                 | промис готовности соответствий                          |
| `isEnabled()`                                           | включён ли тумблер                                      |

Потребители: `courses/tasks_fix.js` (метод скипа, веса, дедлайны, а также
фильтр по курсам — он показывает переименованное название, но хранит и
сравнивает оригинал),
`course-view/future_exams_view.js` (расписание контрольных ищется по названию),
`course-view/exams_dashboard.js` (по оригиналу находит родную карточку курса, чтобы
перейти на курс без перезагрузки),
`course-view/course_friends_list.js` (совпадение курсов с друзьями),
`course-view/course_cards.js` (ключ иконки и архива).

### `settings_registry.js`

Единый список настроек расширения и перенос их в JSON. Подключается **только
попапом** (тегом `<script>`), контент-скриптам не нужен. Формат файла описан
отдельно: [`PROFILE-FORMAT.md`](../../../PROFILE-FORMAT.md).

**Зачем.** Настройки раскиданы по двум хранилищам и десятку плагинов: тумблеры
и списки — в `storage.sync`, картинки и названия — в `storage.local`, токены
интеграций — там же рядом. Пока единственным «списком всего» был попап,
выгрузить настройки в файл было нельзя: непонятно, что выгружать, а что трогать
нельзя. Реестр отвечает на три вопроса — какие ключи бывают, что из них
переносится, и годится ли то, что приехало в чужом файле.

**Группы.** `appearance`, `features`, `integrations`, `content` (свои
картинки), `personal` (названия курсов, архив, скрытые задания архива и
скрытые курсы сводной таблицы) и `private` — последняя не
попадает в файл никогда: токены АКХ, ключ устройства биржи, кеши, `lmsOrigin`.
Отдать токен вместе с настройками означало бы отдать доступ к аккаунту.

**Наборы.** `settings` — только поведение (килобайты), `visual` — оформление и
картинки (мегабайты, картинки лежат `data:`-URL внутри JSON), `full` — всё
плюс личное.

**Проверка на загрузке.** Каждый ключ ищется в реестре и проверяется по типу,
диапазону и списку допустимых значений; не прошедшее пропускается с причиной, а
хранилище не трогается. Разбор (`inspect`) и запись (`apply`) разделены: попап
сначала показывает, сколько применится и сколько пропустится, и спрашивает
подтверждение — загрузка перезаписывает настроенное руками.

**Значения по умолчанию.** У записи есть `fallback` — что показывать, когда
ключа в хранилище ещё нет. Оно обязано совпадать с тем, что подставляет сам
плагин: попап рисовал галочку как `!!undefined`, то есть «выключено», а
`friends_tab.js` считал `data.friendsEnabled !== false`, то есть «включено» —
на свежей установке вкладка друзей была на месте, а галочка говорила, что её
нет. Теперь попап берёт значение по умолчанию из реестра (`defaultFor`).

**Правило на будущее:** новый ключ хранилища заводится в реестре сразу. Ключ,
которого там нет, просто не перенесётся, а вот забытый секрет в группе
`content` утечёт вместе с паком. И если плагин считает настройку включённой
при отсутствии ключа — это должно быть записано в `fallback`.

### `custom_background.js`

Своя картинка вместо заливки страницы — общая на все страницы LMS или своя
для страницы, курса или раздела (см. ниже и редактор фона). Тумблер «Своя
картинка на фоне» (`customBackgroundToggle` в `storage.sync`), картинка — в
`storage.local.customBackground`, рядом `backgroundFit`
(`cover` / `contain` / `fill` / `tile` / `none`) и `backgroundVeil` (0–95 %, по умолчанию 60).

**Два подхода, которые не работают.**

1. _Переопределить переменную темы._ Заливку рисует не один слой:
   `cu-sidebar-layout` берёт цвет из `--sidebar-layout-content-background-color`,
   внутренний `cu-<раздел>-layout` — из `--accent-pale`, а в узкой раскладке
   поверх всего ложится `div.content` из компонента сайдбара с `--elevation-01`.
   Перечислить теги тоже нельзя: у каждого раздела свой, а Angular-атрибуты
   (`_nghost-ng-c235008457`) меняются от сборки к сборке.
2. _Сделать слои прозрачными и показать картинку на `html`._ Прозрачность
   обнажает то, что за слоем прячется: в узкой раскладке за `div.content`
   лежит раскрытое меню, и его пункты проступают прямо сквозь карточки.
   Проверено на живой странице — выглядит сломанным.

**Как сделано.** Картинка кладётся **поверх** заливки — на сами слои-полотна,
вместе с `background-attachment: fixed`. Фиксированный фон привязан к окну, а
не к элементу, поэтому несколько слоёв показывают один и тот же кадр и
стыкуются бесшовно, а сам слой остаётся непрозрачным и ничего не обнажает.
`html` получает ту же картинку — на случай, когда страница короче окна.

Слои ищутся **по геометрии, а не по именам**: непрозрачный элемент шире 60 %
окна и площадью больше 40 % экрана — это полотно. Карточки и острова меньше,
под правило не попадают; меню (`cu-sidebar`), шапка (`cu-header`) и диалоги
исключены явно, иначе текст на них стал бы нечитаемым. Обход идёт от `body`
вглубь и обрезается по ширине — считать `getComputedStyle` по всей странице на
каждую мутацию слишком дорого.

Свои островки расширения помечаются атрибутом **`data-culms-island`** и тоже
исключены: они бывают высокими и по площади проходят как полотно. Так было с
дэшбордом контрольных на «Мои курсы» (`course-view/exams_dashboard.js`) —
в невысоком окне он получал картинку фона вместо своей заливки.

**Подложка** — полупрозрачная заливка поверх картинки, цветом самой темы (берём
`background-color` полотна, поэтому в светлой она забеливает, а в тёмной
затемняет). Без неё текст, лежащий прямо на полотне, висит поверх фотографии:
на странице заданий таблица не завёрнута ни в какой островок, и при
`backgroundVeil: 0` она нечитаема — это и была первая жалоба на фичу.

Подложка сделана вторым слоем того же `background-image`, а не отдельной
панелью: на странице курсов картинку рисует внутренний `cu-*-layout`, который
лёг бы поверх такой панели и свёл её на нет. Слоем фона она всегда оказывается
между картинкой и содержимым, не участвует в раскладке и не перехватывает клики.

`MutationObserver` перемечает полотна после перехода в другой раздел, а
слушатель `resize` — после смены ширины окна: набор полотен от неё зависит.
Если у нового раздела другой цвет темы, CSS пересобирается под него.

**Разный фон на разных страницах.** Кроме общей картинки можно поставить
свою на любую «область» — описаны в [`background_scopes.js`](background_scopes.js):

| Область   | Ключ `storage.local`                 | Что охватывает                                 |
| --------- | ------------------------------------ | ---------------------------------------------- |
| `page`    | `customBackground.page:<адрес>`      | ровно эту страницу (курс, лонгрид, что угодно) |
| `course`  | `customBackground.course:<id курса>` | все страницы курса: обзор, темы, лонгриды      |
| `section` | `customBackground.section:<раздел>`  | раздел LMS целиком (см. ниже)                  |
| `all`     | `customBackground`                   | все страницы — это и есть общая картинка       |

На странице побеждает самая узкая область, у которой картинка есть:
страница → курс → раздел → общая. Так можно поставить одну картинку на все
курсы и перебить её у пары любимых. Адрес нормализуется (`/learn/tasks/` и
`/learn/tasks` — одна страница), `actual` и `archived` у курса — один курс.

Разделы — по адресу: `courses` (список курсов), `longreads`, `course`
(страницы курсов), `tasksArchive`, `tasks`, `timetable`, `reports`. Порядок
проверки важен — лонгрид лежит внутри адреса курса, архив внутри задач,
поэтому узкий раздел стоит раньше широкого.

Каждая область — **отдельный ключ**, а не один объект со всеми картинками:
страница читает только свои 2–4 ключа, а правка одной картинки не гоняет
мегабайты остальных через `storage.onChanged` во все вкладки. Прочитанное
кешируется, так что при возврате на страницу хранилище не трогается. Пока
новая картинка читается, на экране остаётся прежняя — мигнуть общей по пути
хуже. Скрипт инжектится один раз на вкладку, поэтому смену страницы ловит сам:
`MutationObserver` на каждой мутации сверяет адрес; следит, пока фон включён,
даже если на текущей странице картинки нет.

Наружу `custom_background.js` отдаёт `window.cuLmsCustomBackground`
(`state()`, `subscribe()`, `refresh()`) — им пользуется редактор.

Ключи областей заведены в реестре настроек одной записью с префиксом
`customBackground.` (группа `content`, уезжают в визуальный пак) — страниц
сколько угодно, перечислить их нельзя. Закреплено тестами
`tests/source/background-scopes.test.ts` и `tests/custom-background-editor.test.ts`.

### `background_editor.js`

Редактор фона прямо на странице. Попап → «Своя картинка на фоне» → кнопка
«Редактор фона» ставит `storage.local.backgroundEditorActive` (и включает
тумблер фона), после чего во всех вкладках LMS в правом нижнем углу
появляется панель:

- адрес страницы и что сейчас на фоне («весь этот курс», «обычная заливка»);
- области этой страницы с миниатюрами и пометкой «на экране»;
- превью картинки выбранной области, «Выбрать картинку» / «Заменить» и
  «Убрать»; файл можно просто перетащить на панель;
- общие «Вставка» и «Подложка» — те же `backgroundFit` и `backgroundVeil`;
- «Готово» и «×» сбрасывают флаг — панель закрывается во всех вкладках.

Человек ходит по LMS как обычно, панель следует за ним: о смене страницы ей
сообщает `custom_background.js` через `subscribe()`. Выбранная область
запоминается при переходах — удобно пройтись по курсам и каждому поставить
свою. Поставил картинку при выключенном тумблере — редактор включит его сам.

Флаг лежит в хранилище, а не в памяти вкладки: панель переживает перезагрузку
и переход по обычной ссылке, а попапу не нужно знать, в какой вкладке человек.
Флаг — в группе `private` реестра: в профиль не уезжает.

Панель — в Shadow DOM, подвешена к `html`, а не к `body`: стили LMS и тёмной
темы красят `button`, `select` и `*` и развалили бы её, а Angular
перерисовывает содержимое `body`. Картинка готовится так же, как в попапе:
svg и файлы до 512 КБ — как есть, анимация до 1 МБ — как есть, тяжелее —
пережимается `gif_reencode.js` (поэтому он теперь инжектится и в `_shared`),
остальное — через canvas в webp до 1920 px.

### `theme_tokens.js`

Каталог цветовых переменных LMS с человеческими подписями:
`{ name, label, hint, group, dark }`. Наружу — `window.cuLmsThemeTokens`.
Подключается и страницей редактора, и контент-скриптом темы: правила сборки
CSS должны быть одни.

Зачем он нужен. Палитра сайта живёт в CSS-переменных, но их сотни, имена вроде
`--tui-background-neutral-1-pressed` ничего не говорят, а наши собственные
переопределения были размазаны по 16 тысячам строк `dark-theme.css` — чтобы
узнать, что именно мы красим, приходилось читать CSS. Теперь набор собран в
одном месте и подписан: что за переменная, где видна и какое значение ей даёт
наша тёмная тема.

Поле `dark` — ровно та строка, что стоит в `dark-theme.css`. Совпадение
проверяет `tests/source/theme-tokens.test.ts`: поменяли значение в теме и
забыли в каталоге — тест упадёт.

Кроме данных отдаёт три функции:

- `normalizeVars(obj)` — выбрасывает незнакомые переменные и значения, которыми
  можно закрыть правило раньше времени (`;`, `}`) и сломать весь блок;
- `normalizeCss(text)` — обрезает свой CSS до `CSS_MAX` (200 КБ);
- `buildCss(vars, css)` — собирает итоговый стиль. Селектор нарочно широкий,
  `:root, :host, [tuiTheme]`: Taiga объявляет переменные и на корне, и на
  `[tuiTheme]`, и объявление на вложенном элементе перебило бы унаследованное.

### `custom_theme.js`

Применяет свою тему на странице: собирает `<style id="culms-custom-theme">` из
`customThemeVars` и `customThemeCss` и держит его в `<head>`. Тумблер —
`customThemeToggle` (`sync`), данные — в `local`.

Стиль обязан лежать **последним** в `<head>`: объявления переменных в
`dark-theme.css` местами помечены `!important`, а среди важных объявлений с
одинаковой специфичностью выигрывает то, что идёт позже. Тёмная тема
вставляется в момент включения тумблера, то есть может приехать уже после нас,
поэтому за порядком следит `MutationObserver` на `<head>`, а не порядок
загрузки скриптов.

Правки применяются без перезагрузки: редактор пишет в хранилище, а
`storage.onChanged` приходит во все вкладки сразу — в этом и смысл «живого»
редактирования.

### `theme_editor_host.js`

Пипетка редактора тем. Сам редактор открыт в соседней вкладке
(`plugins/theme-editor/`), чужой DOM ему не виден — разбирать элементы
приходится здесь.

Жест — **правая кнопка мыши**. Пока вкладка редактора открыта, пипетка
взведена постоянно, и забирать себе левый клик нельзя: по странице надо
продолжать ходить — открывать курсы, разворачивать разделы, доходить до того
самого элемента, который не так покрашен. ПКМ на это не влияет (контекстное
меню подавляется только пока пипетка взведена).

Связь с редактором — через `storage.local`, а не `postMessage`: вкладки
разные, общего окна нет, а `storage.onChanged` приходит во все сразу. Ключи
`themePickerActive` (редактор открыт), `themePageValues` (значения переменных
на этой странице) и `themePickResult` (последний разбор) лежат в группе
`private` реестра и в профиль темы не попадают.

Пока пипетка взведена, элемент под курсором обводится пунктиром, внизу висит
подсказка, а после разбора — всплывашка «смотрите вкладку редактора»: результат
уезжает в соседнюю вкладку, и без неё непонятно, сработало ли. Esc выключает
пипетку со страницы, закрытие вкладки редактора — тоже.

**Выгрузка стилей.** Пипеткой находится не всё: до чего-то не доберёшься мышью
(состояния hover, элементы во всплывашках), а что-то плагин красит правилом, а
не переменной. Поэтому редактор умеет попросить «покажи всё, что красишь»
(`themeSourceRequest`), и сюда собирается ответ (`themeSourceDump`) — тексты
всех наших `<style>` на странице с подписями: тёмная тема, OLED-надстройка,
фон, логотип, своя тема. Это выгрузка живых стилей, то есть ровно то, что
сейчас применено, а не файл из репозитория.

Вкладок с LMS может быть несколько, и каждая полезла бы отвечать одним и тем же
(а это полмегабайта), поэтому ответы разъезжаются случайной задержкой и вторая
вкладка видит, что ответ уже лежит, и молчит.

Как разбирается элемент:

- **селектор** строится от тега, осмысленного `id` и не-служебных классов;
  сгенерированные Angular и Taiga (`ng-*`, `_ng*`, `cdk-*`) отбрасываются —
  они меняются от сборки к сборке. Если селектор задевает больше одного
  элемента, к нему приписывается родитель, до трёх уровней;
- **цвета** берутся из computed style, но только осмысленные: `border-color`
  без рамки, `fill` у не-SVG и `outline-color` без обводки посчитаны всегда и
  только закопали бы настоящие цвета элемента в шум;
- **переменные** — те из каталога, что вычисляются на элементе и совпали по
  цвету с одним из его свойств. Сравнение идёт не по тексту: одна и та же
  краска записана то `#e8eaed`, то `rgb(...)`, то через `var()`, поэтому
  значения прогоняются через скрытый элемент и сравниваются уже как
  `rgb(r, g, b)`.

Клик в режиме пипетки гасится (`preventDefault` + `stopPropagation`): иначе
разбор цветов уводил бы со страницы по первой же ссылке. Esc отменяет.

### `custom_logo.js`

Меняет логотип ЦУ в левом верхнем углу на свою картинку — на всех страницах
LMS. Тумблер «Свой логотип ЦУ» (`customLogoToggle` в `browser.storage.sync`),
сама картинка — в `browser.storage.local.customLogo` как data-URL.

**Почему не подменой картинки.** Логотипа как картинки в DOM нет: у ссылки
`cu-navigation-link.header__logo-link a` в инлайновом стиле лежит
`--t-icon-start: url(assets/cu/icons/cuIconLogo.svg)`, а псевдоэлемент
`::before` рисует эту **CSS-маску**, закрашивая её цветом текста. Поэтому
плагин снимает маску (`mask-image: none`, иначе поверх нашей картинки виден
закрашенный силуэт родного логотипа), гасит `background-color` (им Taiga красит
маску) и кладёт свою картинку фоном с `background-size: contain`.

Наблюдателя за DOM нет и не нужно: правило живёт в одном `<style>` на весь
документ, так что сколько бы Angular ни перерисовывал шапку, оно продолжает
действовать. Перерисовка по изменению настроек — через `storage.onChanged`,
поэтому логотип меняется без перезагрузки страницы.

Коробка под логотип — 180×32 (на узком экране LMS сама подставляет короткий
знак), то есть широкая полоска. Картинка обычных пропорций вписывается в неё по
высоте и занимает лишь левый край, поэтому режим вставки вынесен в настройку
`logoObjectFit`: `contain` (по умолчанию, вся картинка целиком), `cover`
(заполнить и обрезать), `fill` (растянуть, пропорции не сохраняются) и `none`
(пиксель в пиксель). Рядом `logoScale`, 25–400 %.

Масштаб делается через `transform: scale()`, а не через `background-size`: так
он работает одинаково при любом режиме вставки. Точка отсчёта — левый край,
чтобы логотип рос вправо. На раскладку это не влияет (`transform` не меняет
размер коробки), но за отведённые 180×32 картинка при увеличении выходит и
может наехать на меню — об этом сказано в подсказке в попапе.

Файл готовит попап, и **по тем же правилам, что картинки курсов**: он
подключает общий `plugins/course-view/gif_reencode.js` обычным тегом `<script>`
и спрашивает у него, анимированный ли файл. Вектор отдаётся как есть, анимация
до 1 МБ — как есть, анимация тяжелее пережимается в компактный GIF (с
подтверждением от 3 МБ, потому что это секунды работы), всё остальное до 256 КБ
идёт как есть, а что крупнее — ужимается до 600 px и пережимается в webp с
прозрачностью. Потолок на исходник — 64 МБ.

**Надпись «НЕ ЯВЛЯЕТСЯ ОФИЦИАЛЬНОЙ LMS».** Свои картинки курсов, свои
названия и картинка на фоне дают страницу, которую легко выдать за настоящую
LMS. Поэтому, когда хоть одна из них действует, фирменный логотип
принудительно заменяется сплошной красной плашкой (`#e00000`) с белой надписью в две строки.
Цвет задан жёстко, а не из темы: `--tui-status-negative` в LMS местами
указывает на бледный `--negative-pale`, и надпись почти не читалась.
Отдельного тумблера у неё нет; убрать её можно только своим логотипом —
своя картинка всегда важнее надписи.

«Действует» значит: тумблер включён и в нём что-то есть.

| Что              | Тумблер (`sync`)          | Данные (`local`)                     |
| ---------------- | ------------------------- | ------------------------------------ |
| Картинки курсов  | `oldCoursesDesignToggle`  | `courseIcons` — хоть одна картинка   |
| Названия курсов  | `customCourseNamesToggle` | `courseNames` — хоть одно название   |
| Картинка на фоне | `customBackgroundToggle`  | любая область `background_scopes.js` |

Надпись показывается на всех страницах, а не только там, где видна
переделка: скриншот любой страницы с такими настройками уже не официальный.
Надпись — это `content` того же псевдоэлемента: размеры, которые LMS задаёт
под логотип (180×32, на узком экране 48×32), сбрасываются, и плашка берёт
ширину по тексту. Шрифт указан явно — Taiga ставит иконкам `font-size: 1.5rem`.

Ключи областей фона заранее неизвестны, поэтому их список собирается перебором
`storage.local`: через `getKeys()`, где он есть, иначе чтением хранилища
целиком. Делается это только при включённом фоне, а дальше список
поддерживается по `storage.onChanged`. Картинки курсов тоже читаются, только
когда включён их тумблер. Оттого `custom_logo.js` в манифесте стоит после
`background_scopes.js`.

### `cu-clubs.js` + `cu-clubs.css`

Добавляет в левое меню LMS вкладку «Клубы ЦУ» и рисует на странице записи
(`/learn/timetable#cuclubs`) список мероприятий студенческих клубов вместо
обычного расписания.

**Как работает:**

1. `injectSidebarTab()` клонирует нативный пункт «Запись на пары» из
   `ul.nav-list`, меняет ему иконку, `aria-label`, подпись и `href` на
   `/learn/timetable#cuclubs`, после чего дописывает в конец списка.
2. При клике переходит на страницу записи и ставит хэш `#cuclubs`;
   `handlePageRender()` прячет `cu-student-timetable-events`, подменяет
   последнюю крошку на «Клубы» и рендерит свой контейнер
   `#cu-clubs-container` со списком мероприятий.
   Хэш чистится через `history.replaceState()`, как только пользователь уходит
   с `/learn/timetable`: пока `#cuclubs` в адресе, Angular подставляет его во
   все ссылки сайдбара. `replaceState` не поднимает `hashchange`, поэтому
   рекурсивного перерендера не возникает.
3. `updateSidebarState()` держит подсветку активного пункта: на странице клубов
   активна наша вкладка, а не «Запись на пары».
4. `MutationObserver` на `document.body` перезапускает `handlePageRender()`, так
   что вкладка восстанавливается после любых перерисовок Angular.

**Важно про поиск шаблона.** Пункт ищется не по
`[automation-id="sidebar-item-timetable"]`, а сравнением `pathname` ссылки с
`/learn/timetable`. Две причины:

1. LMS проставляет `automation-id` только в **свёрнутом** сайдбаре: в
   развёрнутом пункты рендерятся через `cu-sidebar-tree-item` и уже без этого
   атрибута — из-за чего вкладка «Клубы» появлялась только при свёрнутом меню.
2. Сравнивать `href` целиком тоже нельзя: если сайдбар пересобирается, пока в
   адресе висит наш `#cuclubs`, Angular дописывает текущий фрагмент **во все**
   ссылки меню (`/learn/timetable` → `/learn/timetable#cuclubs`,
   `/learn/tasks` → `/learn/tasks#cuclubs` и т.д.). При точном сравнении шаблон
   переставал находиться, и на странице клубов вкладка пропадала после любого
   сворачивания/разворачивания меню.

Свою вкладку исключаем по `data-cu-clubs`: на странице клубов её href совпадает
с нативным символ в символ.

**Важно про крошки.** Крошка «Клубы» — это отдельный элемент
`a.cu-clubs-crumb` (клон нативной через `cloneNode(false)`, чтобы сохранились
`_ngcontent-*` и стили), а нативная `.breadcrumbs__item_last` просто прячется
через `display: none`. Раньше текст переписывался прямо в нативной крошке, а
исходное значение хранилось в `dataset.originalText` и возвращалось при уходе
со страницы. Узел принадлежит Angular и переиспользуется между разделами,
поэтому «восстановление» периодически срабатывало уже после того, как Angular
отрисовал крошку нового раздела, и затирало её — на странице курса в крошках
оставалось «Запись на пары». Свой узел Angular не трогает, а восстанавливать
нечего: он просто удаляется, а с нативного снимается `display`.

Сайдбар полностью пересобирается при сворачивании/разворачивании, поэтому
наличие вкладки проверяется в текущем `ul.nav-list`, а осиротевшие копии
удаляются. В развёрнутом виде у пункта есть подпись
`.cu-navtab__main-element-text` — её тоже надо переименовать, иначе вкладка
называлась бы «Запись на пары».

На мобильной ширине (`cu-sidebar.mobile.collapsed`) списка `ul.nav-list` в DOM
нет вообще — вкладка появляется, когда пользователь открывает меню.

**Взаимодействие со страницей:**

- Читает DOM: `ul.nav-list`, `li.nav-list__item`, `cu-navtab`,
  `.cu-container.sidebar__content`, `cu-student-timetable-events`
- Вставляет: `li.cu-clubs-tab` в меню, `#cu-clubs-container` в контент
- Fetch: список мероприятий клубов с внешнего API
- Хранилище: `browser.storage.sync` (`themeEnabled`, `oledEnabled`)

### `plugin_page_loader.js`

Добавляет кнопку расширения в шапку сайта и открывает по ней встроенное меню настроек.

**Как работает:**

1. Вставляет кнопку (иконку) в `ul.header__actions-list`.
2. По клику открывает оверлей (`#cu-plugin-overlay-container`), внутри которого
   лежит `<iframe>` с попапом расширения (`popup/popup.html`) — это и есть меню.
   Ширина обёртки задана явно: `min(740px, calc(100vw - 80px))`. Явно — потому
   что обёртка лежит во flex-контейнере, который ужимается по содержимому, и
   гибкий iframe схлопывался в свою `min-width`.
3. Новости из GitHub Gist живут в свёрнутой панели справа
   (`#cu-plugin-gist-right-panel`) и открываются кнопкой «Что нового» в углу
   оверлея. Раньше панель занимала полэкрана и открывалась всегда: настроек она
   закрывала больше, чем показывала новостей. Содержимое тянется при первом
   открытии панели, а не при открытии меню — обычно оно не нужно. Пока панель
   открыта, обёртка расширяется до `min(1260px, calc(100vw - 80px))`, чтобы
   новости не отъедали место у настроек.
4. При закрытии меню через `postMessage` спрашивает у iframe, были ли изменены настройки, и при необходимости перезагружает страницу.
5. Тема оверлея и кнопки синхронизируется с `browser.storage.sync`.

**Взаимодействие со страницей:**

- Читает DOM: `ul.header__actions-list`
- Вставляет: кнопку в шапку, `<div>` оверлея с `<iframe>` в `document.body`
- Fetch к GitHub Gist для загрузки правой панели

### `safari_navigation.js`

Восстанавливает обнаружение SPA-навигации в Safari.

**Как работает:**

- В Safari отслеживает изменение `location.href`, включая переходы через
  `history.pushState` и `history.replaceState`, которые не всегда попадают в
  `webNavigation`.
- Отправляет новый URL в background с action `SAFARI_NAVIGATION`, после чего
  background запускает подходящие плагины для новой страницы.
- В Chrome и Firefox завершается сразу: их существующий путь через
  `webNavigation.onHistoryStateUpdated` не меняется.

### `snow.js`

Анимация падающего снега поверх страницы.

**Как работает:**

1. Читает флаг `snowEnabled` из `browser.storage.sync`.
2. Если включено — создаёт `<canvas>` с `position: fixed; z-index: 9999` и запускает анимацию 150 снежинок через `requestAnimationFrame`.
3. Подписывается на `storage.onChanged` и мгновенно включает/выключает снег при изменении настройки.

**Взаимодействие со страницей:** вставляет `<canvas>` в `document.body`, не трогает DOM самой страницы.

### `icons_color_fixer.js`

Исправляет цвет конкретных SVG-иконок, которые некорректно отображаются при нестандартных темах.

**Как работает:**

- Применяет CSS-фильтр `brightness(0) invert(1)` к `tui-icon`-элементам, чей атрибут `style` совпадает с именами из списка `TARGET_ICONS`.
- `MutationObserver` следит за появлением новых иконок и изменением их `style`.

**Взаимодействие со страницей:** только чтение/изменение атрибутов `<tui-icon>`, DOM не перестраивает.

### `apricot_api.js`

- Отвечает за интерфейс в веб-странице: `window.__akhCheckApi`.
- Методы:
  - `fetchCourseDetails(courseId)`
  - `fetchTaskProgress(taskId)`
  - `fetchAllProgress()`
- Работает через `CustomEvent` и `AKH_PROXY_REQUEST`/`AKH_PROXY_RESPONSE_*`.

### `akh_bridge.js`

- Слушает `AKH_PROXY_REQUEST` и пересылает запрос в фон через `chrome.runtime.sendMessage`.
- Возвращает ответ обратно в страницу через `AKH_PROXY_RESPONSE_<id>`.
- Обрабатывает JSON из-за особенностей Firefox (строка или объект).

### `apricot_tasks_fix.js`

- Включает отображение статусов Apricot в таблице задач LMS.
- Находится в `plugins/courses/apricot_tasks_fix.js`.
- Логика:
  - Периодически (каждые 3 секунды) проходит по строкам задач
  - Нормализует названия (`normalize`): удаляет "ДЗ N", "неделя N", спецсимволы и лишние пробелы
  - Находит совпадения среди задач/групп Apricot
  - Выбирает статус с максимальным приоритетом (Rework > On review > Accepted > None)
  - Добавляет бейдж `AKH: STATUS` в столбец статуса

### `token_grabber.js`

- Берёт токены из `localStorage:
  - access: `auth-token` / `access`
  - refresh: `refresh-token` / `refresh_token` / `auth-refresh` / `refresh`
- Посылает `chrome.runtime.sendMessage({action: 'AKH_SAVE_TOKENS', access, refresh})`.

### Как ориентация

- Все эти скрипты работают вместе: `token_grabber` даёт токен, `apricot_api` - интерфейс, `akh_bridge` - прокси, `apricot_tasks_fix` - отображение.
- Цель — показать текущие статусы Apricot задач внутри LMS без переписывания интерфейса LMS.

## Интеграция с Яндекс.Контестом (`YandexContestServices` в `background.ts`)

Вторая внешняя интеграция, устроенная проще AKH: page-context и мост не используются,
потому что токены не нужны. Контент-скрипт `plugins/courses/contest_tasks_fix.js` работает
в isolated world и шлёт в фон одно сообщение `CONTEST_FETCH_PROGRESS`. Вся сеть — в фоне.

**Откуда берутся данные:**

- Ссылка на контест лежит в `exercise.exerciseUrl` карточки задачи
  (`/api/micro-lms/tasks/{taskId}`). Поле универсальное: там же встречаются
  `git.culab.ru`, `self-service.culab.ru` и т. п., поэтому фильтруем по хосту
  `contest.yandex.ru`. В списке `/api/micro-lms/tasks/student` этого поля нет,
  а `exercise.type` равен `coding` практически у всех задач и фильтром служить не может.
- Прогресс — со страницы `/contest/<id>/problems/`. Она серверная и содержит
  `div.solution-status` для **каждой** задачи контеста, поэтому одного запроса хватает
  на весь контест. Модификатор `solution-status_color_green` означает полное решение.
- В service worker нет `DOMParser`, поэтому разбор идёт regex-ом по BEM-разметке
  (`parseProblems`). Вкладки «Задачи»/«Посылки» отсеиваются, так как ведут на
  `/problems/` без алиаса.

**Бюджет запросов** (главная причина трёхуровневого кеша):

| Запрос                | Количество      | TTL кеша                                        |
| --------------------- | --------------- | ----------------------------------------------- |
| список задач студента | 1               | 60 секунд                                       |
| `exerciseUrl` задачи  | 1 на упражнение | 7 дней, в `storage.local`; «ссылки нет» — 1 час |
| страница контеста     | 1 на контест    | 5 минут                                         |

Отрицательные результаты (`exerciseUrl === null`) и ошибки контеста кешируются тоже —
иначе задачи без ссылки перезапрашивались бы при каждом открытии страницы. Но «ссылки нет»
живёт всего час (`EXERCISE_MISS_TTL`): преподаватель нередко публикует задачу раньше, чем
вписывает ссылку на контест, и недельный отрицательный кеш прятал бы её до следующей недели.
У кеша есть `CACHE_VERSION` — при её повышении все записи отбрасываются при загрузке,
иначе отрицательные записи по старым правилам пережили бы обновление расширения. Карточки задач
тянутся пулом из `DETAIL_CONCURRENCY = 3`, чтобы не делать burst из двух десятков запросов.
Повторные `CONTEST_FETCH_PROGRESS` объединяются через `_progressInflight`.

**Состояния ответа:** `ok` (есть `solved`/`total`/`problems`), `not_entered`
(студент не вошёл в контест), `auth_required` (нет сессии Яндекса), `error`.

**Как различаются `not_entered` и `auth_required`.** На `/contest/<id>/enter/` Яндекс уводит
оба случая, поэтому по редиректу их не отличить — различаем по шапке страницы.
Проверка идёт по ПОЛОЖИТЕЛЬНОМУ признаку (`isAuthenticatedHtml`): у авторизованного есть блок
`user-menu`, а в ссылке на поддержку — его логин. Ловить маркеры формы входа ненадёжно,
они отличаются от страницы к странице.

Неуспешные состояния кешируются 60 секунд вместо пяти минут (`CONTEST_FAIL_TTL`):
пользователь логинится и сразу обновляет страницу, ждать он не станет.

**Проверка авторизации для попапа** — действие `CONTEST_CHECK_AUTH` (`checkAuth`), отвечает
`authorized` (+`login`) / `anonymous` / `unknown`, кеш 60 секунд. Нужна отдельно от прогресса,
потому что предупредить надо сразу при включении интеграции, когда курсы ещё не выбраны.
Пробой служит страница демоконтеста: отдельной лёгкой страницы с шапкой у contest.yandex.ru нет
(главная весит больше мегабайта, `/contests/` и `/my/` отдают 404). В отличие от остальных
контестных действий это НЕ спрятано за `contestIntegrationEnabled`: попап спрашивает статус
сразу при включении тумблера, когда внутри iframe изменение ещё не дошло до `storage`.

**Включение:** тумблер «Интеграция с Яндекс.Контестом» в попапе
(`contestIntegrationEnabled`, по умолчанию выключено). При выключенном тумблере
обработчик `CONTEST_FETCH_PROGRESS` сразу отвечает `CONTEST_DISABLED`.

## Фильтр курсов для внешних интеграций

Обе внешние интеграции сканируют только курсы, выбранные пользователем в попапе.
Пустой список означает «не выбрано»: интеграция не делает ни одного запроса.

| Настройка (`storage.sync`) | Интеграция | Где применяется                                                                                             |
| -------------------------- | ---------- | ----------------------------------------------------------------------------------------------------------- |
| `akhCourseFilter`          | AKHCheck   | `tasks_fix.js` не грузит модуль, если список пуст; `apricot_tasks_fix.js` отсеивает чужие строки до запроса |
| `contestCourseFilter`      | Контест    | `YandexContestServices.fetchProgress` фильтрует задачи до запроса карточек                                  |

Формат — массив `{ id, name }`: контест фильтрует по `id` (он есть в API задач),
AKH — по `name` (в DOM таблицы `taskId` и `courseId` отсутствуют, есть только текст).
Имена сравниваются нормализованно, с учётом подмены эмодзи плагином `emoji-swap`.

Список курсов для селекторов попап берёт через действие `LMS_FETCH_COURSES`
(`/api/micro-lms/performance/student?isArchived=false`, URL зафиксирован в фоне).
Курс, выбранный ранее и пропавший из активных, остаётся в списке, чтобы не выпасть из фильтра молча.

`apricot_tasks_fix.js` работает в page-context и до `storage` не дотянется, поэтому
`tasks_fix.js` кладёт имена выбранных курсов в `document.documentElement.dataset.culmsAkhCourses` —
DOM у isolated и main world общий.
